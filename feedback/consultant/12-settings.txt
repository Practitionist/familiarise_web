ISSUES
─────────────────────────────────────────────

[1] 🔴 P0 — "Settings" is not in the sidebar nav — page is hidden (cross-ref: 1-home.txt Issue [1])
The sidebar navigation contains no "Settings" link. The only way to reach the Settings page is via the user avatar dropdown in the top navbar — a non-obvious location that contradicts every convention where "Settings" is a nav item. A consultant who wants to change their availability, pricing, or bank details has no visible path from the sidebar. This issue was also documented in the Home page audit (1-home.txt).

> **Proposed fix:** Add "Settings" as a dedicated nav item in the sidebar — either at the bottom of the primary nav or in a secondary section below the Finance group. The Settings link should use the gear icon and persist across all pages.

[2] 🟠 P1 — No page H1 — heading hierarchy starts at H2
The first heading in the main content area is "Profile Verified" (H2). There is no H1 "Settings" heading on the page. Screen readers navigating by heading will not find an H1, and the heading hierarchy starts at H2 for a page-level concept.

> **Proposed fix:** Add `<h1>Settings</h1>` as the primary page heading before the Profile Verified banner (or use a DashboardHeader component consistent with other pages that have H1s).

[3] 🟠 P1 — Custom Schedule calendar renders alongside Weekly Recurring slots — both visible simultaneously
The Availability Settings section shows both the "Weekly Recurring" slot grid (left column) AND the "Custom Schedule" calendar (right column) side by side, even though "Weekly Recurring" is the selected radio option. These two schedule types are mutually exclusive — a consultant using Weekly Recurring should not see the Custom Schedule calendar at the same time.

> **Proposed fix:** Use conditional rendering: when "Weekly Recurring" is selected, show only the weekly slot grid. When "Custom Schedule" is selected, hide the weekly grid and show only the calendar date picker. Do not display both simultaneously.

[4] 🟠 P1 — No "Pricing" or "Banking/Payout" sections in Settings
The Settings page covers Profile, Availability, and Notifications. There is no section for:
  (a) Pricing — setting consultation/subscription rates (currently only editable in the Event Planner dialog)
  (b) Banking — adding/editing bank account details for receiving payouts
A consultant who wants to update their bank details after onboarding has no path in the dashboard. This is a critical missing feature for the Finance workflow.

> **Proposed fix:** Add a "Payout & Banking" section to Settings with: bank account number, IFSC code, account holder name, and UPI ID (for Indian consultants). Add a "Pricing Defaults" section with default hourly rate. Both can link to their respective management pages if they exist elsewhere.

[5] 🟠 P1 — Single global "Save Changes" button for the entire page — no per-section save
The entire page (Professional Profile + Enhanced Profile + Availability + Notifications) is saved via one "Save Changes" button at the very bottom. A consultant who changes their professional headline (top of page) and then accidentally toggles a notification preference (bottom) will save both changes. The form is long — multiple distinct domains of settings should have independent save controls.

> **Proposed fix:** Split the settings page into sections with individual "Save" buttons per section. Or implement auto-save with a change indicator per section. At minimum, add a sticky "Save Changes" button in the page header that appears once any field is modified.

[6] 🟠 P1 — Professional Summary contains lorem ipsum placeholder text
The Professional Summary textarea is pre-filled with "Volaticus deserunt volutabrum vulnero vitium solitudo alienus vereor. Totam amita coma. Coniuratio comprehendo cerno." — a Latin faker.js string. This is seed data that would appear on Andrew's public consultant profile page.

> **Proposed fix:** Update seed.ts to use a realistic professional summary for the Health Consultant profile. Pattern: "[X] years of experience in [domain]. Specializes in [topics]. Clients describe sessions as [style]. Booking available Mon–Fri."

[7] 🟡 P2 — Social links, languages, and tools fields contain random faker.js data
Website: numb-digit.info (random domain), GitHub: Tremayne_Kuvalis47 (random name), Twitter: Sandy_Lehner23, LinkedIn: Kendall75. Languages: "Spanish, French, Russian, Portuguese" (no English). Tools: "Telehealth Platforms, Health Analytics, Patient Management, EMR Systems, HIPAA Compliance" (plausible for a Health Consultant but inconsistent with Career Coach headline). These are realistic-looking but wrong, which is more misleading than obviously fake.

> **Proposed fix:** Update all seed profile data to be internally consistent for each consultant persona. For "Andrew Anderson — Health Consultant | Career Coach": website = "andrewanderson.health", languages = "English, Hindi", GitHub/Twitter/LinkedIn = coherent branded handles.

[8] 🟡 P2 — Emoji in heading elements (📅, 🎯) — accessibility concern
The headings "📅 Schedule Type Filtering" (H3) and "🎯 Custom Schedule" use emoji as decorative prefixes inside ARIA heading roles. Screen readers will read the emoji name ("calendar" and "direct hit" respectively) which adds noise to screen reader navigation. Emoji in headings also look inconsistent with the rest of the dashboard's heading style.

> **Proposed fix:** Move emoji to `aria-hidden="true"` `<span>` elements before the heading text, or remove them entirely and rely on icons from the icon system.

[9] 🟡 P2 — "Schedule Type Locked" uses H5 — too many heading levels deep
The "Schedule Type Locked" alert box uses an H5 heading inside the Availability section (H2 → H3 → H5 skipping H4). H5 is unnecessarily granular for a warning message.

> **Proposed fix:** Use a `<strong>` or `<b>` element for the "Schedule Type Locked" label instead of an H5. Alert content doesn't need to participate in the heading hierarchy.

[10] 🟡 P2 — "17 valid slots (17h total) — Ready to proceed" counter needs explanation
The availability slot summary shows "17 valid slots (17h total) — Ready to proceed" but doesn't explain what "valid" means (not overlapping? In the future? Correct duration?). "Ready to proceed" has no action button attached to it — it's a passive status that offers no guidance on next steps.

> **Proposed fix:** Add a tooltip on "valid" explaining: "Slots with no conflicts and within future scheduling periods." Add a "Save Availability" button next to the summary, or make the counter part of the "Save Changes" button context.
