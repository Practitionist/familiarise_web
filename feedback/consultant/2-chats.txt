VISUAL OBSERVATIONS
─────────────────────────────────────────────
The Chats page renders a Stream Chat component split into two panels:
- LEFT PANEL (blue background, ~200px wide): Stream sidebar with header "Familiarise", search box, "Channels" section, "Conversations" section, and two footer buttons.
- RIGHT PANEL: "No channel selected — Select a channel from the sidebar to start chatting"

Channels section: "No team channels found."
Conversations section: "No conversations yet. Book a consultation to start chatting."

A badge "1" is visible on the Chats nav link in the sidebar, suggesting an unread message/channel, but no conversations are actually visible in the Stream panel. This is likely a stale/unresolved count.

─────────────────────────────────────────────
A11Y OBSERVATIONS
─────────────────────────────────────────────
- The Stream left panel header uses <h1>Familiarise</h1> (uid=8_0) — semantically incorrect inside a page that already has a document title. Screen readers will announce two competing h1s.
- "Chats" nav link has no accessible badge label for the unread count; the count badge is purely visual.
- "Initialize My Channels" button (uid=8_8): no aria-description, no context — a screen reader user would have no idea what this does.
- "Debug Stream Chat" button (uid=8_9): haspopup="dialog" — screen readers will announce "button, collapsed, has popup dialog" with no further context.
- No ARIA live region for when channels load asynchronously — screen reader users get no feedback.

─────────────────────────────────────────────
ISSUES
─────────────────────────────────────────────

[1] 🔴 P0 — "Initialize My Channels" and "Debug Stream Chat" are dev-only buttons visible to all users
Both buttons appear prominently at the bottom of the Stream sidebar in what would be a production view:
- "Initialize My Channels" (black, solid button) — triggers a channel initialization routine. Should only be accessible via developer tools or an admin panel.
- "Debug Stream Chat" (blue link-styled button, opens a dialog) — a debugging utility for inspecting Stream state.
These buttons were seen in the consultee audit as well (same root issue). A production user interacting with "Initialize My Channels" could trigger duplicate channel creation or other side effects.

> **Proposed fix:** Wrap both buttons in a `process.env.NODE_ENV === 'development'` guard so they only render in dev. In production, initialization should happen automatically (on first login or first booking).

[2] 🟠 P1 — Empty state copy is written from the consultee's perspective
"No conversations yet. Book a consultation to start chatting." tells the consultant to "book a consultation" — but consultants don't book, they receive bookings. This copy was clearly copy-pasted from the consultee's Chats empty state without updating the perspective.

> **Proposed fix:** Change to "No conversations yet. Once a consultee books a session with you, your conversation will appear here." Or: "Start chatting by sharing your profile with prospective clients."

[3] 🟠 P1 — Unread badge count on Chats nav link doesn't match visible channel list
The sidebar nav link "Chats" shows a "1" count badge, but the Stream panel shows 0 channels and 0 conversations. The badge count is stale or incorrectly computed (possibly counting an internal/system channel that isn't shown in the UI). This creates a false expectation and erodes trust when users click Chats expecting a message but find nothing.

> **Proposed fix:** Only increment the unread badge from channels that are rendered in the Conversations or Channels list. If the panel shows 0 conversations, the badge must be 0.

[4] 🟠 P1 — Stream chat panel bypasses the standard DashboardHeader layout
All other consultant pages (Home, Appointments, etc.) use a consistent DashboardHeader + DashboardContent shell with a page title in the top navbar area. The Chats page renders the Stream component directly, with no page title visible in the top header ("Chats" is not shown in the main content header bar, unlike other pages). This breaks layout consistency and makes the page look like an embedded iframe rather than a native dashboard page.

> **Proposed fix:** Wrap the Stream chat container in the same DashboardHeader component, setting the page title to "Chats" in the navbar area, and adjusting the Stream component height to account for the header height.

[5] 🟡 P2 — Stream sidebar header "Familiarise" uses H1 tag — wrong semantic level
The Stream left panel renders its header text "Familiarise" as an `<h1>` (uid=8_0). The page document already has an implicit H1 in the page title. An H1 inside a sidebar component breaks document outline semantics and is announced as the primary page heading by screen readers.

> **Proposed fix:** Customize the Stream component's header slot to use `<h2>` or a `<div>` with `role="heading" aria-level="2"`.

[6] 🟡 P2 — No conversation can be clicked; no example of actual chat UX
Because Andrew has 0 Stream channels initialized, no chat conversation is accessible for review. The "Conversations" section is completely empty despite Andrew having 451 appointments. Stream channels should have been auto-created for seed consultant. This blocks full UX validation of the chat experience (message rendering, timestamps, send input, etc.).

> **Proposed fix:** Ensure seed script calls the Stream channel creation API for each seeded appointment. Or provide a "create test channel" button in dev mode.

[7] 🟡 P2 — "Refresh Channels" button (uid=8_1) has no accessible label or tooltip
The button with a refresh icon appears in the header area of the Stream panel. It has no visible text label, only an icon. The a11y label is "Refresh Channels" which is good, but there's no tooltip visible on hover to explain its purpose to sighted users who encounter it without context.

> **Proposed fix:** Add a tooltip on the refresh icon button, or make it labeled with text "Refresh" adjacent to the icon.

[8] 🟡 P2 — No page height cutoff, but minimum height not enforced
The chat panel fills the viewport well and doesn't appear to be cut off. However, on short viewports or zoomed browsers, the empty right panel would have excess dead space. The panel is not given a `min-height` that ensures the right-panel empty state remains centered. (Minor visual polish item.)

> **Proposed fix:** Ensure the chat container has `min-height: 400px` to maintain visual integrity at narrow heights.
