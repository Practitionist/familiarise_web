ISSUES
─────────────────────────────────────────────

[1] 🟠 P1 — All 3 Consultation Plan descriptions contain lorem ipsum text (seed data bleed)
All three Consultation Plan descriptions ("Officiis conor carus tabula nam advoco...", "Infit ars auctor caelestis barba deduco...", "Absconditus adaugeo decens vulgo...") are faker.js Latin placeholder text. Subscription Plan descriptions are real. The inconsistency suggests the Consultation Plan seed factory used lorem ipsum while Subscription Plans were hand-written. Any demo to a real user or investor would immediately show fake content on the most prominent plan type.

> **Proposed fix:** Update seed data to replace the 3 ConsultationPlan descriptions with realistic content matching the plan name (Basic/Extended/Comprehensive). Mirror the quality of the Subscription Plan descriptions.

[2] 🟠 P1 — Plan card action buttons (Edit + Delete) have no accessible labels
Each plan card has exactly 2 unlabelled icon buttons (confirmed as Edit and Delete via interaction). Neither has an `aria-label`, `title`, or visible text. Screen readers will announce them as "button" with zero context, making it impossible for assistive technology users to distinguish Edit from Delete.

> **Proposed fix:** Add `aria-label="Edit Basic Consultation"` and `aria-label="Delete Basic Consultation"` (interpolating the plan name). Also add `title` attributes so sighted users see a tooltip on hover.

[3] 🟠 P1 — Price spinbutton has incorrect ARIA `valuemax="0"` (while actual value is 2985)
In the Edit Consultation Plan dialog, the Price input has `valuemax="0"` and `valuemin="0"` while `value="2985"`. A value exceeding its declared maximum confuses screen readers (announcing "2985 out of a maximum of 0"). The Create Webinar dialog's price input has the same issue. This likely means the `max` prop is not being set on the underlying HTML `<input>` element, defaulting to 0 in the ARIA mapping.

> **Proposed fix:** Set `max={undefined}` or an appropriate large value (e.g. `max={9999999}`) on the price numeric input to ensure ARIA `valuemax` reflects a valid upper bound.

[4] 🟠 P1 — "At least one topic is required" validation error shown in Create Webinar before user interacts
On opening the "Create New Webinar" dialog, the Topics field immediately shows the error "At least one topic is required" in red text, before the user has entered anything or attempted to submit. This is an eager-validation anti-pattern that creates anxiety and looks broken on first impression.

> **Proposed fix:** Only show the topics required error after the user has attempted to submit, or after they've focused and blurred the field without adding a topic. On initial render, show only the placeholder "Add a topic..."

[5] 🟠 P1 — "Live Sessions" stat ("0 Live Sessions") excludes Andrew's 79 webinars and 109 classes
Andrew has 79 webinar and 109 class appointments in the database, but the page shows "0 Live Sessions." The distinction is architectural (the Live Sessions section shows upcoming Webinar/Class *events*, not historical), but with no explanation of this in the UI, a consultant reviewing their stats sees "0" despite significant past activity. A "Total All-Time" count or a "Past Sessions" link would provide context.

> **Proposed fix:** Show two metrics: "0 Upcoming Live Sessions" and "188 Past Live Sessions" (or link to a history view). Or at minimum, change the label to "0 Upcoming Live Sessions" to clarify the scope.

[6] 🟠 P1 — Page title inconsistency: nav says "Event Planner", page says "Event Management"
The sidebar nav link is labelled "Event Planner" but the page's H1 heading reads "Event Management". These must match for navigation clarity (users return to "Event Planner" but land on "Event Management"). The inconsistency is also present in URL (`.../planner`) vs heading.

> **Proposed fix:** Standardize on one name. "Event Planner" is more intuitive for the target audience (actionable, user-centered). Update the H1 heading to "Event Planner" or vice versa.

[7] 🟡 P2 — No Archive option — only hard Delete with no soft-delete
The second card button opens a hard-delete confirmation dialog. There is no "Archive" or "Pause/Unpublish" option. If a consultant wants to stop accepting new bookings on a plan (without destroying historical appointment data), they have no recourse. Deleting a plan with existing appointments could create orphaned data or FK violations.

> **Proposed fix:** Add "Archive" as a distinct action separate from Delete. Archived plans stop appearing on the consultant's public profile but preserve all appointment history. Hard Delete should be blocked (or warn explicitly) if the plan has existing appointments.

[8] 🟡 P2 — Delete confirmation dialog title uses inconsistent terminology ("Delete consultation?")
The alertdialog title reads "Delete consultation?" while elsewhere the UI consistently uses "Consultation Plan." The short form is ambiguous — is it deleting a specific appointment/booking, or the plan template?

> **Proposed fix:** Change dialog title to "Delete Consultation Plan?" and body to "Are you sure you want to delete the plan "Basic Consultation"? All associated plan data will be removed. Existing appointments will not be affected."

[9] 🟡 P2 — "0/1 participants" on Consultation Plans is confusing for a 1:1 service
All plans show "0/1 participants." For consultation plans, this appears to represent "maxEnrollments=1" — meaning 1 consultee at a time. The label "participants" implies concurrent session headcount (as it would for a Webinar). For consultations, the relevant metric is "total bookings" or "active clients", not "participants."

> **Proposed fix:** For CONSULTATION type plans, replace "0/1 participants" with "0 bookings" (total active consultations on this plan), or hide the participant count entirely. Reserve "participants" for Webinar/Class plans where it has meaningful capacity context.

[10] 🟡 P2 — Collaborator add requires two steps (create webinar first, then add)
The Create Webinar dialog shows a "Collaborators" section with the message "Save this webinar first to add collaborators." This forces a consultant to: (1) create and save the webinar, (2) reopen the webinar editor, (3) then add collaborators. This is two saves where one should suffice.

> **Proposed fix:** Allow pre-selecting collaborators during creation. Save them together with the webinar in a single API call. This follows the principle of progressive disclosure — all related data should be configurable at creation time.

[11] 🟡 P2 — Language="German" for seed consultation plan shows unexpected locale in edit form
The Edit Consultation Plan dialog shows Language="German" for Andrew Anderson's Basic Consultation plan. This is random seed data, but it underscores that the seed factory for ConsultationPlan uses faker for the language field, producing unexpected values. If this language value affects consultee-facing plan pages, it could mislead consultees.

> **Proposed fix:** Update seed.ts ConsultationPlan factory to default Language="English" for all seed plans, unless specifically testing multi-language scenarios.
