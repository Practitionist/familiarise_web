ISSUES
─────────────────────────────────────────────

[1] 🔴 P0 — "Join (Dev)" button is a dev-only bypass visible in production
Angela Brown's consultation and Aarav Brown's subscription both show a green "Join (Dev)" button. This button bypasses the normal 5-minute pre-session join window and allows the consultant to enter a session at any time. This is a development testing tool that MUST NOT reach production — it circumvents the intended UX gate and exposes the join flow to premature use.

> **Proposed fix:** Wrap "Join (Dev)" in `process.env.NODE_ENV === 'development'` guard. The production "Join" button should only appear within the intended time window.

[2] 🔴 P0 — 440+ appointments invisible: no pagination, no filter, no "view all" — critical data loss
Andrew has 79 consultations, 184 subscriptions, 79 webinars, 109 classes = 451 total appointments. The page shows only 3 consultations and 6 subscriptions (~9 total). There is no pagination control, no "Load more" button, no filter bar, and no count indicator on section headings. A consultant with 200 clients cannot see the vast majority of their appointment history. Webinars and Classes sections show "No X scheduled" despite 79+109 existing rows — likely a filter bug (showing only upcoming, not historical).

> **Proposed fix:** (a) Add section-level counts in headings (e.g. "Consultations (79)"). (b) Add pagination (page 1 of N) or infinite scroll per section. (c) Add a filter/search bar (by consultee name, date range, status). (d) Investigate why Webinars/Classes sections show empty — likely a date filter excluding past rows.

[3] 🟠 P1 — "Not Scheduled" shown in red in both date field AND status badge — double negative messaging
Cards with unscheduled appointments show "Starts: Not Scheduled" (in red text, in the date area) AND a red "Not Scheduled" badge in the top-right corner. This doubles up the same message redundantly and the red color creates undue alarm — "Not Scheduled" is a neutral state (awaiting availability setup), not an error.

> **Proposed fix:** Consolidate to one placement (badge only, or date-area only). Change badge color from red to gray/amber to signal "action needed" without implying error.

[4] 🟠 P1 — No "Unscheduled Events" section for webinars/classes needing slot allocation
The plan protocol called for a section showing "Unscheduled Events" — webinars and classes that have been booked but have no slot allocated yet. The page doesn't have this section. Andrew has 79 webinars and 109 classes, presumably some awaiting slot assignment. A consultant with event-type services needs a clear queue of "these events need a timeslot" separate from the appointment view.

> **Proposed fix:** Add an "Action Required" or "Unscheduled Events" panel above the main sections, listing webinars/classes with no SlotOfAppointment, with a CTA to the Event Planner or Requests page.

[5] 🟠 P1 — Webinars and Classes sections always say "No X scheduled" — filtering excludes historical
Both "Webinars" and "Classes" sections display "No webinars scheduled" and "No classes scheduled." Given Andrew has 79 webinars and 109 classes in the DB, the filter appears to be excluding past/completed events. If the intention is "upcoming only," there is no way to view past webinar/class attendance. This is a significant gap — consultants reviewing historical class data have no path.

> **Proposed fix:** Add a "Past" toggle or tab (e.g. "Upcoming | All | Past") per section, or at the page level, so historical appointments are accessible.

[6] 🟠 P1 — No search or filter bar across 451 appointments
The page has no search input and no filter UI. A consultant managing 451 appointments across 4 types cannot search for a specific consultee, filter by status (Completed, Not Started, Not Scheduled), or filter by date range. At scale, this page is unusable for any task beyond checking the 3–6 most recent upcoming items.

> **Proposed fix:** Add a persistent filter bar at the top of the page with: (a) text search by consultee name, (b) type filter checkboxes (Consultation/Subscription/Webinar/Class), (c) status filter, (d) date range picker.

[7] 🟡 P2 — Free Trials sub-section absent from Subscriptions group
The protocol specifically checked for a "Free Trials" sub-section under the SUBSCRIPTION group (to show trial-to-subscription conversions). No such sub-section exists. Andrew has 0 TrialSession rows but even structurally the Subscriptions section has no Free Trials grouping visible, making trial tracking inaccessible from the Appointments view.

> **Proposed fix:** Add a collapsible "Free Trials" sub-section within the Subscriptions group, or add a link to the Free Trials page from the Subscriptions section header.

[8] 🟡 P2 — No section-level counts on section headings
Section headings "Consultations", "Subscriptions", "Webinars", "Classes" don't show total counts (e.g. "Consultations (79)"). A consultant cannot determine at a glance how many total appointments exist per type.

> **Proposed fix:** Append count in parentheses to each section heading: "Consultations (79)", "Subscriptions (184)", etc.

[9] 🟡 P2 — "Participants" button on consultation cards (1:1 sessions) is misleading
Consultations are 1:1 sessions — there is only ever 1 participant. Having a "Participants" button (which implies a multi-person list) on consultation cards is misleading. Webinar/Class "Participants" makes sense; Consultation should show "Details" or just display the consultee name directly.

> **Proposed fix:** Hide the "Participants" button for CONSULTATION type appointments, or rename it to "Details" for 1:1 contexts.

[10] 🟡 P2 — Subscription progress bar present but not self-explanatory
Victoria Anderson shows "1 completed / 0 remaining / 1 of 1 sessions" with a blue progress bar. The progress bar itself is a nice visual, but the stat line reads: "1 completed" / "0 remaining" / "1 of 1 sessions" — three separate text nodes rendering the same information three times. Redundant.

> **Proposed fix:** Consolidate to: progress bar + a single line "1 / 1 sessions completed". Remove the separate "X completed" and "Y remaining" text nodes.
