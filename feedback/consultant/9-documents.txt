ISSUES
─────────────────────────────────────────────

[1] 🟠 P1 — Page heading "Documents For Review" is H2 — no H1 on the page
The primary heading `<h2>Documents For Review</h2>` is the only heading on the page. There is no H1. Screen readers will not find any H1 and may report the page as having poor document structure. Compare with Free Trials page which correctly uses H1 for its primary heading.

> **Proposed fix:** Change the heading level to H1 (or H2 if nested inside a DashboardHeader that already has an H1). Ensure all pages in the consultant dashboard use H1 for their primary title.

[2] 🟠 P1 — Status badge renders raw ALL_CAPS "PENDING" — not human-readable
The Status column displays "PENDING" in uppercase, the raw enum value from the database. This is inconsistent with the Review dialog's status dropdown which correctly uses human-readable "Pending." The badge and the dialog represent the same field — they should match in casing.

> **Proposed fix:** Humanize the status badge to Title Case: "Pending", "In Review", "Approved", "Rejected", "Needs Revision" — matching the dropdown options in the Review dialog.

[3] 🟠 P1 — "View" button opens a new tab that fails to load — signed URL issue
Clicking "View" on the document row opens the document URL in a new browser tab. The tab errored (chrome-error://chromewebdata/), indicating the URL is either: (a) a Supabase signed URL that has expired, or (b) an invalid placeholder from seeding. Supabase signed URLs expire by default. If a consultant tries to view a document uploaded more than N hours ago, the URL may silently fail with a blank/error page and no explanation.

> **Proposed fix:** (a) Generate a fresh signed URL on each "View" click (call the Supabase `createSignedUrl` API server-side at click time, then redirect), rather than storing a static URL. (b) Add error handling: if the signed URL fetch fails, show a toast "Could not open document — try again." Do not open a blank tab.

[4] 🟠 P1 — "Appointment" column shows internal document ID (DOC-f2de0d59) instead of a useful reference
The Client column shows "Ananya Brown / DOC-f2de0d59" and the Appointment column shows "Comprehensive Subscription / subscription." The "DOC-f2de0d59" ID is a truncated internal database UUID — it has no meaning to the consultant. The "subscription" label is also a raw lowercase enum value leaked into the UI.

> **Proposed fix:** Remove the internal doc ID from the Client column. In the Appointment column, show only the human-readable plan name ("Comprehensive Subscription"). The service type label should be Title Case: "Subscription" not "subscription."

[5] 🟡 P2 — Nav link "Documents" vs page heading "Documents For Review" — inconsistency
The sidebar nav says "Documents" but the page says "Documents For Review." These two labels should match for navigation clarity.

> **Proposed fix:** Standardize to "Documents" in both the nav and the page heading (the subtitle "Review documents submitted by your consultees and subscribers" already explains the purpose). Or change the nav label to "Documents for Review" to match.

[6] 🟡 P2 — Upload Date includes seconds — excess precision
The Upload Date column shows "08/02/2026 / 05:51:57" with second-level precision. Consultants need to know the approximate date and time a document arrived, not the exact second. The seconds make the column wider and harder to scan.

> **Proposed fix:** Display as "Feb 8, 2026 at 5:51 AM" — human-readable, locale-appropriate, no seconds. (Same issue noted on Trials and Requests pages.)

[7] 🟡 P2 — Action buttons "View", "Download", "Upload Response" are icon-only with no visible tooltip
The three icon buttons in the Actions column have accessible names in the a11y tree ("View", "Download", "Upload Response"), but visually they appear as icon-only buttons with no visible text or hover tooltip. A consultant unfamiliar with the icon set won't know which icon uploads vs downloads vs views.

> **Proposed fix:** Add `title` attributes so a tooltip appears on hover. Or display text labels below the icons. At minimum, the Upload Response icon (an arrow-up icon) is not universally understood and needs a tooltip.

[8] 🟡 P2 — No status filter tabs — document queue is unsortable at scale
The page has no filter tabs (All | Pending | In Review | Approved | Rejected), no search bar, and no sort control. A consultant with many documents has no way to prioritize which ones need action (Pending vs. already Approved). At scale this becomes a serious usability gap.

> **Proposed fix:** Add status filter tabs above the table: "All | Pending | In Review | Approved | Rejected | Needs Revision." Default to "Pending" to surface action-required items first.
