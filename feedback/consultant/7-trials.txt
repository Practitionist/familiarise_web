ISSUES
─────────────────────────────────────────────

[1] 🟠 P1 — Status badges use raw enum format (ALL CAPS: PENDING, SCHEDULED, CONVERTED)
All status badges render in ALL CAPS: "PENDING", "SCHEDULED", "COMPLETED", "CONVERTED". This is raw enum formatting, not human-readable UI copy. The stat filter buttons at the top correctly use Title Case ("1 Pending", "1 Scheduled") but the in-card badges don't match. The inconsistency breaks visual coherence.

> **Proposed fix:** Humanize all status badge labels to Title Case: Pending, Scheduled, Completed, Converted, Cancelled, Declined. Apply the same transformation as used in the stat buttons.

[2] 🟠 P1 — Redundant dual filter system: stat buttons AND "All Statuses" dropdown do the same thing
The page has two independent status filter mechanisms: (1) the 6 colored stat buttons at the top (which appear clickable as filters) and (2) the "All Statuses" dropdown below. Both filter by trial status. This creates confusion about which one is active and whether they interact with each other.

> **Proposed fix:** Remove the dropdown and use only the stat button strip as the primary filter (already shows counts, color-coded, more scannable). Or vice versa. Don't provide two mechanisms for the same action.

[3] 🟠 P1 — "Join Meeting" button is disabled with no explanation why
Patrick Anderson (SCHEDULED) shows a disabled "Join Meeting" button. There is no tooltip, helper text, or time indicator explaining when the button will become active. A consultant checking a scheduled trial at 9am might not know it enables 5 min before the session start time.

> **Proposed fix:** Add a tooltip on the disabled button: "Available 5 minutes before the scheduled time." Or add a countdown: "Joins in 2h 15m."

[4] 🟠 P1 — CONVERTED trials show no link to the resulting subscription
Rachel Anderson and Raj Anderson show "CONVERTED" status but there's no indication of which subscription plan they converted to or a link to view their subscription. A key metric for the consultant — "which of my trials are converting to which plans?" — cannot be answered from this view.

> **Proposed fix:** For CONVERTED trials, add a line below the plan name: "→ Converted to Comprehensive Subscription" with a link to the consultee's subscription appointment card.

[5] 🟡 P2 — Consultee email addresses are exposed on trial cards (privacy concern)
Each card shows the consultee's full email address (olivia.anderson@gmail.com, patrick.anderson@outlook.com, etc.) as secondary text. In a dashboard that may be screen-shared or screen-recorded (e.g. during training sessions), displaying full email addresses increases PII exposure risk.

> **Proposed fix:** Mask emails by default (e.g. "o***@gmail.com") with an option to reveal on click. Or rely on the avatar + name alone for identity, showing email only in a details modal.

[6] 🟡 P2 — "30 min trial" appears hardcoded on all cards regardless of subscription plan
All 5 trials show "30 min trial" — Basic, Extended, and Comprehensive Subscription plans all show the same duration. If the trial duration is configurable per subscription plan, this is a bug. If it's fixed at 30 minutes, the label adds no information and could be removed or noted once at the page level.

> **Proposed fix:** If duration is plan-configurable, read it from the SubscriptionPlan.trialDuration field and display the actual value. If it's always 30 min, document this in the UI (e.g. "All trials are 30 minutes") rather than repeating it per card.

[7] 🟡 P2 — "Refresh" button was disabled on initial page load (timing bug)
During the audit's first visit (0 trials), the Refresh button rendered as disabled. After data was inserted and the page was reloaded, it was enabled. This suggests the Refresh button is toggled disabled during the initial data fetch and only re-enabled on completion — but the timeout caused it to stay disabled visually. On slow connections, users may see a permanently disabled Refresh.

> **Proposed fix:** Ensure the Refresh button's disabled state is bound to an explicit loading boolean, not to the absence of data. If loading is complete (success or error), the button should always be enabled.

[8] 🟡 P2 — COMPLETED trials with no "Convert" CTA miss a revenue opportunity
Priya Anderson's trial is COMPLETED but not CONVERTED. There is no "Follow up" button, "Send invite to subscribe" action, or "Mark as converted" CTA. A completed trial that hasn't converted is a warm lead — the page provides no nudge to take action.

> **Proposed fix:** For COMPLETED (non-converted) trials, add a "Invite to Subscribe" action button that sends a Novu/email notification with a subscription link. This converts the completion page into a sales funnel stage.
