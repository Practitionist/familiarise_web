Payments Tab — PM Review

🔴 Critical: Data Issues

1. Currency mismatch — stats show ₹ but transaction shows £
   The three summary stat cards display amounts in Indian Rupees (₹0.00).
   The single transaction in the table displays the amount in British Pounds:
   "£31.99". These two currency symbols should never coexist on the same
   financial page. Either:
   (a) The payment was captured in GBP while the platform defaults to INR, or
   (b) The transaction amount column is not normalising/converting to the
       platform's base currency before display.

   This is a P0 financial trust issue. A user seeing ₹0.00 total spent but
   a £31.99 transaction in the table will not trust either number.

2. "0 transactions" stat despite a visible transaction row
   Total Spent shows "0 transactions" in the subtitle, but there is one row
   in the Transactions table (4 Mar 2026 — FAILED). The stat appears to be
   correctly excluding FAILED payments from the total amount (reasonable),
   but the "0 transactions" label is misleading because a row is visible.
   Options:
   - Change subtitle to "0 successful transactions" to be accurate, or
   - Count all transactions including FAILED (and show ₹0.00 as 0 net spend).

---
🟠 High: UX / Display Issues

3. Coupon code rendered inline in the Amount column
   The transaction row shows the amount as "£31.99" with "MEFSHNKF applied"
   in green underneath — both inside the Amount column. Coupon/promo
   information is not amount data. It should have a dedicated "Discount"
   column or be shown as a tooltip on the amount, not merged into the
   same column. The current layout would break badly with a long coupon code
   or a discount value.

4. No "Retry Payment" CTA for FAILED transactions
   The only data on the FAILED row is a red "FAILED" badge with no recovery
   path. Users need a way to retry the payment, update their payment method,
   or contact support — all from this row. Without this, a failed payment
   is a dead-end that forces users to navigate away or contact support
   through an unrelated channel.

5. Invoice column is empty for the FAILED transaction
   Invoice # shows "—" and the Invoice column also shows "—". For a FAILED
   payment this is understandable (no invoice was issued). However, there is
   no contextual note explaining why — users may wonder if their invoice is
   missing or not generated yet.

6. No filtering or sorting on the transactions table
   At scale with monthly recurring subscriptions across multiple plans, a
   user could have 50+ transactions. There is no date range picker, no filter
   by status (FAILED / SUCCEEDED / REFUNDED), no filter by type (Consultation /
   Subscription / Webinar / Class), and no column sorting. This table will
   become unusable.

---
🟡 Medium: Missing Features

7. No payment method information shown
   Users cannot see which card/UPI/wallet was charged. For dispute resolution
   or receipt verification this is critical. At minimum, show the last 4 digits
   of the card or the payment gateway used (Stripe / Razorpay / Lemon Squeezy).

8. No export / download of transaction history
   There is no way to download a CSV or PDF of all transactions. Users who
   need this for personal finance tracking or expense reporting (business
   accounts) have no path.

9. Credits tab empty state is actionable but vague
   "No credits yet. Refer friends to earn credits!" is a fine empty state,
   but there is no mention of the credit value (₹X per referral), no link
   to the Referrals tab, and no explanation of how credits apply at checkout.

10. "Total Spent" excludes FAILED but that is not communicated
    The logic excluding FAILED from the total is correct business logic, but
    it is invisible to the user. A user who paid ₹5,000 across 10 bookings
    and had 2 FAILED attempts would see ₹5,000 with "8 transactions" — and
    wonder why their bank shows 10 charges. A note like "Successful payments
    only" under the label would prevent confusion.
