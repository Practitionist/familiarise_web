Home Tab — PM Review

🔴 Critical: Logic Bugs

1. EXPIRED appointment in Upcoming Sessions carousel with a "Join" button
   Basic Consultation (Maria Anderson, Mon 30 Mar 2026, 9:30 PM) renders in the
   Upcoming carousel with status "EXPIRED" and a live "Join" button. An expired
   appointment is not joinable and should not appear in the Upcoming section at
   all. This is the same root bug reported in b.txt for the Appointments tab —
   the sort pushes inactive items to the end but doesn't filter them out.

2. PENDING subscription 66 days out shows "Join" button
   Basic Subscription (Charlotte Anderson, Tue 19 May 2026, 10:30 PM) appears
   in the Upcoming carousel with status "PENDING" and a "Join" button. A pending
   appointment has no confirmed slot — joining is impossible. The Join CTA must
   be gated: show it only when the session is within a joinable window AND the
   booking is APPROVED/SCHEDULED.

3. "Join" button on sessions 12–64 days away
   Every card in the Upcoming carousel carries a Join button regardless of how
   far out the session is. Sessions 12, 15, 16, 18, 20, 43, 52, 64, 66 days
   away all show Join. Join should only activate within a narrow window before
   the session start (e.g. 15 minutes). Premature Join buttons train users to
   click them and get errors.

🟠 High: Data & Display Issues

4. "Hours Learned: 30h" = Sessions Completed: 30 — suspicious 1:1 formula
   The stats row shows Sessions Completed: 30 and Hours Learned: 30h — an
   exact 1:1 ratio. This strongly implies the value is computed as
   completedSlotCount × 1h (or DEFAULT_MEETING_DURATION). If sessions vary in
   duration (some 30-min consultations, some 2-hour classes), this number is
   wrong. There is also no way for the user to verify or understand how it was
   calculated — no tooltip or breakdown.

5. "Active Programs: 14" and "Experts Consulted: 14" are identical
   Both stats show 14. Either this is a genuine coincidence in the seed data,
   or they are derived from the same query (e.g., distinct appointmentIds or
   planIds), making one of them redundant. At minimum both need a definition
   tooltip. At worst, one of them is counting incorrectly.

6. Monthly section (March 2026) shows EXPIRED appointment
   The left-side monthly list includes "Basic Consultation — Maria Anderson —
   EXPIRED". A monthly view meant to help users plan their upcoming schedule
   should not include terminal-state events. EXPIRED items should be filtered
   out or moved to a separate "Past this month" subsection.

7. Monthly section shows events without times
   The monthly list rows show: consultant avatar, event name, type badge,
   status badge — but no time. Users cannot plan their day without knowing
   when the event occurs. The Upcoming carousel cards do show times; the
   monthly list does not.

---
🟡 Medium: Missing Context & Polish

8. Stats have no tooltips or calculation context
   "Sessions Completed", "Hours Learned", "Active Programs", "Experts
   Consulted" — none have tooltips. Users don't know if "Active Programs"
   means currently enrolled and not cancelled, or includes PENDING ones. This
   erodes trust in the numbers.

9. No "Today's Sessions" call-out
   The Home page is the first thing a user sees. If today is March 14 and
   William has a class at 2:30 PM, there should be a prominent "Today"
   section or banner above Upcoming Sessions, not just a carousel where
   today's card sits somewhere in the middle.

10. Pending Payments widget has no navigation link
    The right-side "Pending Payments" widget shows "No pending payments —
    You're all caught up!" — fine for this user. But there is no link to the
    full Payments tab from this widget. If a payment does appear, users need
    a clear CTA to resolve it, not just a list item.

11. Greeting is static — "Good evening" hardcoded regardless of time zone
    The snapshot shows "Good evening, William". If this is a server-rendered
    string that doesn't update in real time or adapt to the user's local time
    zone, it will display the wrong greeting for users in different time zones
    or if the value is stale.
