Waitlists Tab — PM Review

🔴 Critical: Logic Bugs

1. Past events appear in the active waitlists list with no warning
   "Advanced Topics Webinar" with Lauren Anderson is dated Mar 13, 2026 at
   9:30 PM — yesterday (today is Mar 14). The event has already occurred, yet
   the card still appears in the active waitlist with "View Event" and "Leave"
   as if it is upcoming. A user on this waitlist will never get a spot because
   the event is over. There is no "Event has passed" indicator, no auto-removal,
   and no explanation. This is the most urgent issue on this page.

   Affected: Lauren Anderson — Advanced Topics Webinar, Mar 13, 2026
   Also check: Mar 20 / Mar 26 / Mar 27 / Mar 28 items as they approach.

---
🟠 High: UX / Display Issues

2. All cards show only event name — no instructor, no date distinguishing
   The page header shows "My Waitlists — You're on 7 waitlists" and the cards
   do include date and instructor. However the section headers are just
   "Webinars (4)" and "Classes (3)" — no sub-grouping. If a user were on 10
   different "Advanced Topics Webinars" (different instructors, same name),
   they would need to scan dates carefully to differentiate them. The card
   layout is fine but the sections offer no help.

3. No past vs upcoming separation within sections
   The four webinars are ordered: May 28 / Mar 28 / Mar 13 (past!) / Mar 20.
   The Mar 13 past event appears between two upcoming ones. There is no
   chronological sort within sections and no visual divide between past and
   future waitlists. Correct order should be: upcoming events first
   (soonest first), past events clearly marked or moved to a "Closed" section.

4. No total waitlist size shown
   William is "Waitlist Position #1" on three events and "#2" on two others.
   But there is no context: is he #1 of 1 (basically confirmed) or #1 of 30?
   The information gap prevents users from making informed decisions about
   whether to stay on the waitlist or book elsewhere.

5. Destructive "Leave" action has no confirmation dialog
   Clicking "Leave" on any waitlist card presumably removes the user from the
   waitlist permanently. There is no confirmation step visible. This is a
   common source of accidental data loss, especially since the button is
   rendered in red and right next to "View Event".

---
🟡 Medium: Missing Features & Polish

6. No notification preference on individual waitlists
   Users have no way to say "notify me by email / SMS / push when I move up"
   per waitlist entry. If a user is #1 on a popular event, missing the
   notification window could mean losing the spot.

7. No filter or sort controls
   With 7 entries spread across two event types, the page is manageable. But
   at scale (20+ waitlists), users need to filter by event type (Webinar /
   Class), sort by date, or filter by position rank (show me #1s first).

8. Only Webinars and Classes — Consultations not represented
   The page shows sections for Webinars (4) and Classes (3). The schema
   supports a Waitlist model that could apply to any appointment type. If
   consultations don't have waitlists, that's a known product scope decision,
   but it should be surfaced — e.g., "Consultation plans don't currently
   support waitlists." Absence of any mention could confuse users who
   wonder why their consultation doesn't appear.

9. "Joined Feb 23, 2026" — date-only, no relative context
   The "Joined" timestamp shows an absolute date. For events months away, a
   user who joined weeks ago might appreciate knowing "You joined 19 days ago"
   as relative context.
