# 4.1 — Consultant Single-Active-Session Concurrency, GiST Constraints (`23P01`), Check Constraints (`23514`) & Owner Transfer

> **Required reading:** [`_shared/shared-setup.md`](../_shared/shared-setup.md),
> [`_shared/mcp-recipes.md`](../_shared/mcp-recipes.md),
> [`_shared/case-template.md`](../_shared/case-template.md).
> **Regression Pin:** Verifies Issue #2010 Part 2 & PR #2012 database-enforced single-active-session consultant concurrency across all 5 appointment types (`CONSULTATION`, `SUBSCRIPTION`, `WEBINAR`, `CLASS`, `TRIAL`).

**Surface(s) under test:**
- `prisma/sql/check-constraints.sql:100–119` — `occurrence_no_confirmed_overlap` (GiST `23P01`) & `occurrence_confirmed_requires_consultant_chk` (`CHECK` `23514`)
- `app/api/bookings/webinars/crud-with-plan/route.ts:863–877, 1005–1058` & `app/api/bookings/classes/crud-with-plan/route.ts:1006–1011` — Owner transfer `PATCH` cascading `consultantProfileId` to live occurrences
- `lib/booking/class-sessions.ts:482–534` & `lib/db/pg-errors.ts:50–56` — `addClassSession` / make-up session catching `23P01` (`isExclusionViolation`) -> HTTP `409 Conflict`

**Workflow roster (5 workflows):**
1. **Workflow 4.1.1 (P0 — DB Kernel)** — `occurrence_no_confirmed_overlap` rejects overlapping confirmed occurrences across any pair of `{CONSULTATION, SUBSCRIPTION, WEBINAR, CLASS, TRIAL}` (`SQLSTATE 23P01`)
2. **Workflow 4.1.2 (P0 — DB Kernel)** — `occurrence_confirmed_requires_consultant_chk` rejects any non-tentative live occurrence with `consultantProfileId = NULL` (`SQLSTATE 23514`)
3. **Workflow 4.1.3 (Corner)** — Webinar/Class owner transfer via `PATCH` cascades `consultantProfileId` onto all non-terminal occurrences and rejects if target consultant is booked
4. **Workflow 4.1.4 (Edge)** — Class make-up session (`addClassSession`) onto an occupied consultant window translates PostgreSQL `23P01` into clean HTTP **`409 Conflict`**
5. **Workflow 4.1.5 (Edge)** — `CANCELLED`, `RESCHEDULED`, and soft-deleted (`deletedAt IS NOT NULL`) tombstones do **not** block re-booking the exact same `[startsAt, endsAt)` window

---

## Workflow 4.1.1: GiST Exclusion Constraint Across All 5 Offering Types (`SQLSTATE 23P01`)

### Step-by-Step Execution
1. **[Supabase MCP]** Execute isolated transaction probe (`mcp-recipes.md §4`) attempting to shift Class occurrence `7b778b43-53ca-4e4b-992e-34f5d4f201c2` (`consultantProfileId = '314eecae-2d84-453b-8f24-825519a3ebb1'`) to overlap Webinar occurrence `e2ccb6d2-26b3-4860-9f27-336af511bf21` (`[startsAt, endsAt)`):
   ```sql
   BEGIN;
     UPDATE "AppointmentOccurrence"
     SET "startsAt" = (SELECT "startsAt" FROM "AppointmentOccurrence" WHERE id = 'e2ccb6d2-26b3-4860-9f27-336af511bf21'),
         "endsAt"   = (SELECT "endsAt"   FROM "AppointmentOccurrence" WHERE id = 'e2ccb6d2-26b3-4860-9f27-336af511bf21'),
         "isTentative" = false
     WHERE id = '7b778b43-53ca-4e4b-992e-34f5d4f201c2';
   ROLLBACK;
   ```

### Expected Invariants & Assertions
- Postgres immediately aborts the statement with **`ERROR: 23P01: conflicting key value violates exclusion constraint "occurrence_no_confirmed_overlap"`**.
- Zero confirmed overlaps can ever be persisted for `314eecae-2d84-453b-8f24-825519a3ebb1` across `CONSULTATION`, `SUBSCRIPTION`, `WEBINAR`, `CLASS`, or `TRIAL`.

## Workflow 4.1.2: Null `consultantProfileId` Bypass Prevention (`SQLSTATE 23514`)

### Step-by-Step Execution
1. **[Supabase MCP]** Execute isolated probe attempting to clear `consultantProfileId = NULL` on a live confirmed occurrence:
   ```sql
   BEGIN;
     UPDATE "AppointmentOccurrence"
     SET "consultantProfileId" = NULL, "isTentative" = false
     WHERE id = 'e2ccb6d2-26b3-4860-9f27-336af511bf21';
   ROLLBACK;
   ```

### Expected Invariants & Assertions
- Postgres immediately aborts with **`ERROR: 23514: new row for relation "AppointmentOccurrence" violates check constraint "occurrence_confirmed_requires_consultant_chk"`**.

## Workflow 4.1.3: Webinar/Class Owner Transfer `PATCH` Cascades `consultantProfileId`

### Step-by-Step Execution
1. **[Chrome DevTools]** As an authorized admin/owner, call `PATCH /api/bookings/webinars/crud-with-plan` transferring `consultantProfileId` to a secondary consultant:
   - Case A: Secondary consultant has an overlapping confirmed session -> returns `409 Conflict`.
   - Case B: Secondary consultant is free -> returns `200 OK` and updates `AppointmentOccurrence.consultantProfileId` in lockstep.

### Expected Invariants & Assertions
- No orphaned occurrences retain the previous consultant's `consultantProfileId`.

---

## Workflow 4.1.4: Class Make-Up Session Conflict Maps `23P01` -> HTTP `409 Conflict`

### Step-by-Step Execution
1. **[Chrome DevTools]** Call `POST /api/classes/<classId>/make-up` (or add session route) requesting a time window where `314eecae-2d84-453b-8f24-825519a3ebb1` already has a confirmed Consultation (`635b4463-e2d9-4890-a9d2-4cfb76d39838`).

### Expected Invariants & Assertions
- `isExclusionViolation(error)` (`lib/db/pg-errors.ts:50–56`) translates Postgres `23P01` into `ScheduleConflictError` -> HTTP **`409 Conflict`** (never an unhandled `500` Prisma error).

## Workflow 4.1.5: Tombstoned (`CANCELLED` / `RESCHEDULED` / `deletedAt`) Slot Reuse

### Step-by-Step Execution
1. **[Supabase MCP]** Inside `BEGIN; ... ROLLBACK;`, insert an occurrence with `completionStatus = 'CANCELLED'` (or `RESCHEDULED`, or `deletedAt = NOW()`) at the exact same `[startsAt, endsAt)` as active Webinar `e2ccb6d2-26b3-4860-9f27-336af511bf21`.

### Expected Invariants & Assertions
- Insert **succeeds** inside the transaction before `ROLLBACK`, proving historical audit rows never block re-scheduling cancelled windows.
