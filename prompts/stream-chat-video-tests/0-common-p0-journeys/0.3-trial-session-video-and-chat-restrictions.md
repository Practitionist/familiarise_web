## Workflow 0.3.2: In-Call Chat Strictly Disabled on `TRIAL` Sessions (Client + Server)

### Step-by-Step Execution
1. **[Chrome DevTools]** Inside `/meetings/<trialMeetingId>` (`MeetingRoom.tsx`), inspect `GET /api/meetings/<trialMeetingId>/session` JSON payload and snapshot the call control bar.
2. **[Chrome DevTools]** Attempt server action / API call to create or fetch an in-call chat channel for the `TRIAL` appointment via `evaluate_script`.

### Expected Invariants & Assertions
- `session` payload explicitly flags `appointmentsType: "TRIAL"` (or `chatEnabled: false`); `MeetingRoom` hides/disables the in-call chat drawer button.
- Server channel guard rejects channel creation for `TRIAL` appointments (`403` / `trial_chat_disabled`).

### Step-by-Step Execution
1. **[Supabase MCP]** Verify no confirmed `CONSULTATION` or `SUBSCRIPTION` exists between the test consultee and consultant (or temporarily test with a fresh consultee who only holds a `TRIAL` seat).

### Step-by-Step Execution
