## Workflow 1.2.1: Collaborator Invite, `Serializable` Acceptance & Stream Channel Sync

### Step-by-Step Execution
1. **[Chrome DevTools / API]** As Primary Consultant (`cmu15jwjr0000c7yobiusdtlt`), invite a secondary consultant as `CO_HOST` (`revenueShareBps = 2500`) on Webinar plan.
2. **[Chrome DevTools / API]** Authenticate as the invited consultant and accept the invitation (`respondToInvitation`).
3. **[Stream IO MCP]** Query `mcp__stream-io__chat_query_members` for `team:webinar-<webinarId>`.

### Expected Invariants & Assertions
- DB row transitions `PENDING` -> `ACCEPTED` under `Prisma.TransactionIsolationLevel.Serializable`.
- Collaborator is synced into `team:webinar-<webinarId>` with `channel_role: "channel_moderator"`.

## Workflow 1.2.2: Single Presenter Partial Unique Index & 90% Revenue Cap Enforcement

### Step-by-Step Execution
1. **[Supabase MCP]** Inside `BEGIN; ... ROLLBACK;`, attempt to insert a second `PENDING` or `ACCEPTED` `WebinarCollaborator` with `role = 'CO_HOST'` on the same `webinarPlanId`.
2. **[Chrome DevTools]** Attempt to invite a collaborator with `revenueShareBps = 9500` (leaving host < `MIN_HOST_SHARE_BPS = 1000`).

### Expected Invariants & Assertions
- DB rejects duplicate `CO_HOST` via `collaborator_one_presenter_webinar` (`SQLSTATE 23505`).
- Service rejects `revenueShareBps > 9000` with `400 Bad Request` (`MIN_HOST_SHARE_BPS = 1000`).

## Workflow 1.2.3: Collaborator Acceptance Blocked on Overlapping Confirmed Session

### Step-by-Step Execution
1. **[Supabase MCP]** Ensure the invited `CO_HOST` already holds a confirmed non-tombstoned `AppointmentOccurrence` overlapping the target Webinar's `[startsAt, endsAt)`.
2. **[Chrome DevTools]** Attempt to accept the `CO_HOST` invitation via API/UI.

### Expected Invariants & Assertions
- Acceptance is rejected with `409 Conflict` (`assertCollaboratorsAvailableForWindows`); status remains `PENDING`.

---

## Workflow 1.2.4: Collaborator Removal Revokes Video & Chat Access

### Step-by-Step Execution
1. **[Chrome DevTools]** Remove/withdraw the collaborator from the Webinar plan and trigger channel sync.
2. **[Chrome DevTools]** Attempt `POST /api/meetings/<meetingId>/join` as the removed collaborator.

### Expected Invariants & Assertions
- `resolveMeetingAccess` returns `403 Forbidden`; Stream Chat `syncEventChannelCore` removes the user from `team:webinar-<id>`.
