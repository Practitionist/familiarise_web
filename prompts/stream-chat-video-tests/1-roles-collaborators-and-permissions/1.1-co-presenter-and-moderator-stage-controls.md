# 1.1 — Roles, Collaborators & Stage Controls: Co-Presenter (`CO_HOST` / `CO_INSTRUCTOR`), `MODERATOR` & Stage Permissions

> **Required reading:** [`_shared/shared-setup.md`](../_shared/shared-setup.md),
> [`_shared/mcp-recipes.md`](../_shared/mcp-recipes.md),
> [`_shared/case-template.md`](../_shared/case-template.md).

**Surface(s) under test:**
- `lib/collaborators/roles.ts:5–19` — `PRESENTER_ROLES` (`CO_HOST`, `CO_INSTRUCTOR` -> `"PRESENTER"`) vs `CREW` (`MODERATOR`, `TEACHING_ASSISTANT`, `CONTENT_CURATOR`)
- `lib/meetings/access.ts:344–378` — `resolveMeetingAccess` mapping accepted presenter collaborators to `role: "host", coPresenter: true`
- `app/api/meetings/[meetingId]/join/route.ts:27–31, 65–110` — `CO_PRESENTER_CALL_ROLE = "co_presenter"` with `CALL_MEMBER_ROLE = "call_member"` fallback + `STREAM_PUBLISH_PERMISSIONS = ["send-audio", "send-video", "screenshare"]`
- `app/api/meetings/[meetingId]/stage/route.ts:34–164` — `POST /api/meetings/[meetingId]/stage` (`grant` / `revoke`)

**Workflow roster (5 workflows):**
1. **Workflow 1.1.1 (P0)** — Accepted `CO_HOST` (Webinar) / `CO_INSTRUCTOR` (Class) joins backstage & receives `co_presenter` + publish capabilities
2. **Workflow 1.1.2 (P1)** — `MODERATOR` (`CREW` tier) joins as `call_member` with publish revoked by default, while holding `channel_moderator` in Stream Chat
3. **Workflow 1.1.3 (P1)** — Host/Co-Presenter promotes learner to stage (`POST /api/meetings/[meetingId]/stage` `action: "grant"`) & revokes (`action: "revoke"`)
4. **Workflow 1.1.4 (Edge)** — Graceful fallback from `co_presenter` to `call_member` when Stream dashboard custom role is absent (`!isUnknownRoleRejection`)
5. **Workflow 1.1.5 (Security)** — Regular learner blocked (`403 Forbidden`) from calling `/stage` (`grant`), `/live`, and `/end`

3. **[Stream IO MCP]** Query both `video_query_call_members` (`default:occurrence-...`) and `chat_query_members` (`team:webinar-<webinarId>`).

## Workflow 1.1.4: Unknown Custom Role Fallback (`co_presenter` -> `call_member`)

### Step-by-Step Execution
1. **[Chrome DevTools & Network Inspection]** Inspect `POST /api/meetings/<meetingId>/join` latency and response when a `coPresenter: true` collaborator joins an environment where `co_presenter` is or isn't defined on `default` call type (`join/route.ts:69–79`).

### Expected Invariants & Assertions
- `join/route.ts` never returns `500 Internal Server Error` if Stream rejects `role: "co_presenter"` as an unknown custom role; it catches `isUnknownRoleRejection(memberError)`, retries `updateCallMembers` with `role: "call_member"`, and still grants `STREAM_PUBLISH_PERMISSIONS`.
