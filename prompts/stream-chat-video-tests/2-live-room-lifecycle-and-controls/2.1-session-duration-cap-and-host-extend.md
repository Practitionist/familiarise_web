# 2.1 — Live Room Controls: Session Duration Cap (`resolveMaxCallDurationSeconds`) & Host `+15m` Extend (`POST /api/meetings/[meetingId]/extend`)

> **Required reading:** [`_shared/shared-setup.md`](../_shared/shared-setup.md),
> [`_shared/mcp-recipes.md`](../_shared/mcp-recipes.md),
> [`_shared/case-template.md`](../_shared/case-template.md).

**Surface(s) under test:**
- `lib/meetings/duration-cap.ts:15–39` — `resolveMaxCallDurationSeconds` (`bookedMs + 45m` clamped to `[2700s, 43200s]`, `CORRUPT_SLOT_FALLBACK_SECONDS = 7200s`)
- `app/api/meetings/[meetingId]/extend/route.ts:87–336` — `EXTENSION_SECONDS = 900`, `buildConflictScope` across host, plan consultant, participants, and co-hosts
- `lib/meetings/access.ts:127–156, 200–214` — Post-grace `callHasLiveParticipants` check (`#1549`) vs `410 Gone reason: "closed"`

**Workflow roster (4 workflows):**
1. **Workflow 2.1.1 (P1)** — Verify initial `limits.max_duration_seconds` formula (`bookedSeconds + 2700`, clamped `[2700, 43200]`) on room creation
2. **Workflow 2.1.2 (P1)** — Host extends live call by `+15m` (`POST /api/meetings/[meetingId]/extend`) when calendar is free
3. **Workflow 2.1.3 (Edge)** — Extension rejected with **`409 Conflict`** (`hasConflictingNextBooking: true`) when host, participant, or co-host has a back-to-back confirmed booking
4. **Workflow 2.1.4 (Edge)** — Rejoin past `endsAt + 30m` succeeds if live participants remain (`callHasLiveParticipants`), else returns `410 Gone reason: "closed"`

## Workflow 2.1.1: Initial Call Duration Cap Clamp Verification

### Step-by-Step Execution
1. **[Supabase MCP]** For a 60-minute `CONSULTATION` occurrence (`3600s` booked), inspect Stream call `default:occurrence-<slotId>` via `mcp__stream-io__video_get_call`.

### Expected Invariants & Assertions
- `call.settings_override.limits.max_duration_seconds === 6300` (`3600s + 900s pre-join + 1800s post-grace = 6300s`).
- For a 15-minute slot, clamped to floor `2700s` (`45m`); for a 12h cohort event, clamped to ceiling `43200s` (`12h`).

## Workflow 2.1.2: Host `+15m` Call Extension (`POST /api/meetings/[meetingId]/extend`)

### Preconditions
- **Supabase Pre-Check:** Ensure next occurrence for Consultant `314eecae-2d84-453b-8f24-825519a3ebb1` and Consultee `euyQyTP7LYjIqguPZWtWOyE5mYl86ud4` is at least `60 minutes` after `endsAt`.

### Step-by-Step Execution
1. **[Auth Injection]** Authenticate as Host `cmu15jwjr0000c7yobiusdtlt` on active meeting `<meetingId>`.
2. **[Chrome DevTools]** Call `POST /api/meetings/<meetingId>/extend` via UI button or `evaluate_script`.

## Workflow 2.1.3: Extension Blocked by Back-to-Back Booking (`409 hasConflictingNextBooking`)

### Step-by-Step Execution
1. **[Supabase MCP]** Place a confirmed `WEBINAR` or `SUBSCRIPTION` occurrence for the same consultant starting `5 minutes` after the current session's `endsAt` (`candidateEndMs = endsAt + 15m > nextBookingStartsAt`).
2. **[Chrome DevTools]** Call `POST /api/meetings/<meetingId>/extend` as Host.

### Expected Invariants & Assertions
- Returns **`409 Conflict`** with JSON `{ extended: false, hasConflictingNextBooking: true, nextBookingStartsAt: "<ISO>" }`.
- Neither Postgres `endsAt` nor Stream `max_duration_seconds` is mutated.

---

## Workflow 2.1.4: Post-Grace Window (`>= endsAt + 30m`) Live Participant Exemption vs `410 Closed`

### Step-by-Step Execution
1. **[Supabase MCP]** Set `endsAt = NOW() - INTERVAL '35 minutes'` on an occurrence whose Stream call has **no** connected participants (`session.participants = []`).
2. **[Chrome DevTools]** Call `POST /api/meetings/<meetingId>/join`.

### Expected Invariants & Assertions
- Returns **`410 Gone`** with `{ reason: "closed" }` when room is empty past `endsAt + 30m` (`#1549`).
