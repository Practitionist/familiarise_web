**Surface(s) under test:**
- `app/api/stream/recordings/start/route.ts:51–296` — Plan `recordingEnabled` check, `getRecordingBlock` opt-out consent (`409 CONSENT_DECLINED` on 1:1 vs group non-blocking), atomic CAS `prisma.meeting.updateMany({ where: { id, isRecording: false, ... } })`
- `app/meetings/[id]/components/EndCallButton.tsx:31–204` & `app/api/meetings/[meetingId]/end/route.ts:15–77` — Deliberate host `endCall` (`410 Gone reason: "ended"`) vs `leaveCall`, and `ended_early` re-provisioning (`occurrence-<slotId>-r<timestamp>`)
- `app/api/stream/webhooks/route.ts:103–279` & `lib/stream/session-handlers.ts` — Gzip magic bytes (`0x1f 0x8b`), HMAC signature check (`401`), `STREAM_REPLAY_WINDOW_MS = 7d`, `STREAM_CLOCK_SKEW_MS = 5m`, `MeetingAttendance` + `MeetingPresence` intervals
- `lib/booking/session-outcome.ts` & `scripts/appointments/auto-complete-appointments.ts` — `decideSlotOutcome` (`HELD`, `LEARNER_ABSENT`, `CUT_SHORT`, `HOST_ABSENT`, `PLATFORM_OUTAGE`, `NOBODY_JOINED`)

**Workflow roster (5 workflows):**
1. **Workflow 2.2.1 (P1)** — Host starts & stops recording (`POST /api/stream/recordings/start`) when enabled, and respects 1:1 participant `DECLINED` opt-out (`409 CONSENT_DECLINED`)
2. **Workflow 2.2.2 (P0)** — Host deliberate **End Call for Everyone** (`POST /api/meetings/[meetingId]/end`) permanently seals room (`410 reason: "ended"`) vs **Leave Meeting** (`call.leave()`) allowing rejoin
3. **Workflow 2.2.3 (Edge)** — Early-ended slot (`endedReason = "ended_early"`) re-provisions a fresh Stream call suffix (`occurrence-<slotId>-r<ts>`) when re-opened
4. **Workflow 2.2.4 (P1)** — `POST /api/stream/webhooks` verifies HMAC signature (`401` on tamper), handles gzip (`0x1f 0x8b`), and records `MeetingPresence` + `MeetingAttendance`
5. **Workflow 2.2.5 (Corner)** — Stale/clock-skewed webhook delivery (`> 7d` past or `> 5m` future) acked with `200 { stale: true }` and routed to `DeadLetterEvent`

## Workflow 2.2.1: Call Recording Consent Gate & Atomic CAS (`POST /api/stream/recordings/start`)

### Step-by-Step Execution
1. **[Supabase MCP]** Insert a `RecordingConsent` row with `decision = 'DECLINED'` for the 1:1 consultee on `<meetingId>`, and ensure plan has `recordingEnabled = true`.
2. **[Chrome DevTools]** As Host (`cmu15jwjr0000c7yobiusdtlt`), call `POST /api/stream/recordings/start` (`{ meetingId }`).
3. **[Supabase MCP]** Flip `RecordingConsent.decision = 'GRANTED'` (or test on a `WEBINAR` group call) and repeat `POST /api/stream/recordings/start`.

### Expected Invariants & Assertions
- On 1:1 with `DECLINED`: returns **`409 Conflict`** with `{ code: "CONSENT_DECLINED" }`; `Meeting.isRecording` stays `false`.
- On `GRANTED` (or `WEBINAR` / `CLASS`): returns `200 OK`, atomically sets `Meeting.isRecording = true, recordingStartedBy = userId`.

## Workflow 2.2.2: Host `endCall` (`410 Ended`) vs `leaveCall` Rejoin Behavior

### Step-by-Step Execution
1. **[Chrome DevTools]** In `MeetingRoom`, host leaves via **Leave meeting** (`call.leave()` without calling `/end`); verify consultee remains in call and host can `POST /api/meetings/<meetingId>/join` (`200 OK`).
2. **[Chrome DevTools]** Host clicks **End call for everyone** (`POST /api/meetings/<meetingId>/end`).
3. **[Chrome DevTools]** Attempt `POST /api/meetings/<meetingId>/join` as either host or consultee.

### Expected Invariants & Assertions
- `POST /api/meetings/<meetingId>/end` sets `Meeting.endedAt = NOW(), endedReason = "call_ended"` and ends the Stream call.
- Subsequent `POST /api/meetings/<meetingId>/join` returns **`410 Gone`** with `{ reason: "ended" }` (`isDeliberateEnd(meeting) === true`).

## Workflow 2.2.3: Fresh Stream Call Allocation After `ended_early`

### Step-by-Step Execution
1. **[Supabase MCP]** Set `Meeting.endedReason = 'ended_early'` on an occurrence that is still inside its valid schedule window.
2. **[Chrome DevTools]** Trigger `provisionAppointmentMeeting` (`getOrCreateAppointmentMeeting`).

### Expected Invariants & Assertions
- `meeting.action.ts:942–949` allocates `occurrence-<slotId>-r<base36Timestamp>` on Stream and resets `endedAt = null, endedReason = null` in Postgres so participants are never blocked by a dead Stream call state.

## Workflow 2.2.4: Webhook HMAC Signature Verification & Attendance Persistence

### Step-by-Step Execution
1. **[Chrome DevTools / Node Fetch]** Send `POST /api/stream/webhooks` with an invalid `X-Signature: deadbeef` header.
2. **[Supabase MCP]** Query `WebhookEvent`, `MeetingPresence`, and `MeetingAttendance` after real participant join/leave events on the deploy preview.

### Expected Invariants & Assertions
- Invalid signature immediately returns **`401 Unauthorized`**.
- Valid Stream webhook persists a durable `WebhookEvent` row before acking `200`, opens/closes `MeetingPresence` intervals, and aggregates `MeetingAttendance.totalDurationSeconds`.

## Workflow 2.2.5: Replay Window & Future Clock-Skew Dead-Lettering

### Step-by-Step Execution
1. **[Supabase MCP / Webhook Inspection]** Inspect `DeadLetterEvent` behaviour when `created_at` exceeds `STREAM_REPLAY_WINDOW_MS` (`7 days`) or `STREAM_CLOCK_SKEW_MS` (`+5 minutes`).

### Expected Invariants & Assertions
- Endpoint returns `200 { received: true, stale: true }` (preventing infinite Stream retry storms) and logs the payload into `DeadLetterEvent`.
