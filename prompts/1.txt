## **CRITICAL BUSINESS RULES TO VERIFY**

### **1. Slot Fundamentals**
- ✅ **1 slot = 30 minutes**
- ✅ **All slots stored in UTC** in database
- ✅ **Displayed in user's local timezone** in UI

### **2. Event-Specific Rules**

#### **Consultations**
- All slots must be **on the same day**
- Must be **consecutive** (e.g., 10:00-10:30-11:00 for 1.5 hours)

#### **Subscriptions**
- **Max 1 call per day**
- **Max `callsPerWeek` calls per week** (Sunday-Saturday weeks)

#### **Classes** (Most Complex!)
- **Each class = 2 consecutive 30-min slots** (1 hour session)

- **Max `callsPerWeek` classes per week**
- Must complete in-progress class before starting another

#### **Webinars**
- Must be **consecutive** (can span midnight/days)
- Single appointment

### **3. Allocation Modes**

-- Verify class allocation constraints
WITH class_slots AS (
  SELECT 
    DATE(sa.slotStartTimeInUTC AT TIME ZONE 'Asia/Calcutta') as session_date,
    sa.slotStartTimeInUTC,
    sa.slotEndTimeInUTC,
    LAG(sa.slotEndTimeInUTC) OVER (PARTITION BY DATE(sa.slotStartTimeInUTC) ORDER BY sa.slotStartTimeInUTC) as prev_end_time
  FROM "SlotOfAppointment" sa
  JOIN "Appointment" a ON sa."appointmentId" = a.id
  WHERE a."classId" = 'class_id'
  ORDER BY sa.slotStartTimeInUTC
)
SELECT 
  session_date,
  COUNT(*) as slots_per_day,
  COUNT(*) / 2 as sessions_per_day, -- 2 slots = 1 session
  -- Check consecutive rule
  SUM(CASE 
    WHEN prev_end_time IS NOT NULL 
     AND EXTRACT(EPOCH FROM (slotStartTimeInUTC - prev_end_time)) > 1 
    THEN 1 
    ELSE 0 
  END) as non_consecutive_gaps
FROM class_slots
GROUP BY session_date
HAVING COUNT(*) / 2 > 2; -- Flag days with >2 sessions
