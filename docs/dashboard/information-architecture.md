# Dashboard information architecture: glossary and current navigation trees

This page records the words the dashboards use for their pages and the navigation trees as the builders in `lib/dashboard/nav/` produce them today. It exists because the same word used to mean different things depending on the role: "Recordings" named sessions you hosted in one dashboard and sessions you attended in another, and "Requests" named booking requests, organization allocation requests or support requests. The rule is one word, one meaning. Permission gating is never changed by a rename or a regrouping; the permission matrices in `lib/auth/org-permissions.ts` and `lib/backoffice/capability.ts` stay the single source of truth.

## Glossary

| Term                            | Means                                                                                                                     | Not to be confused with                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Recordings (in Studio)          | Recordings of sessions you hosted, which you can rename or delete                                                         | Session recordings in Library                                               |
| Session recordings (in Library) | Recordings of sessions you attended (in an organization, also sessions you deliver)                                       | Replays                                                                     |
| Replays                         | A recording listed for sale on the public site; the dashboards no longer sell them                                        | Raw recordings                                                              |
| Digital products                | Files sold or given away, such as e-books, templates and packs; listed in Studio › Products                               | Plan materials                                                              |
| Session documents               | Files exchanged in one specific booking                                                                                   | Plan materials, which are files attached to a plan for its buyers           |
| Billing                         | What you pay, as a learner or as an organization sponsor                                                                  | Earnings, which is what you are paid                                        |
| Booking requests                | Clients asking to book you; the expert Inbox page and the organization page                                               | Booking mode, the setting that decides whether people book instantly or ask |
| Booking mode                    | An expert's setting: instant booking or request first, whether new 1:1 bookings are open, and the cap on waiting requests | Booking requests, the page that lists them                                  |
| Sponsorship programs            | An organization's programs that fund seats for its members (route `programs`)                                             | Group programs, the webinars and classes an expert sells                    |
| Compensation                    | What a hosting organization pays one of its experts (route `compensation`)                                                | Earnings, which is what an independent expert is paid                       |
| Payouts                         | Money sent to a bank account: an organization's runs and payout account, an expert's payout history                       | Billing, which is what you pay                                              |
| Collaborations                  | Invitations to co-host a webinar or class, and the plans co-hosted with others                                            | Collaborators, the people on one plan                                       |
| Catalog                         | The webinar and class plans an organization hosts                                                                         | Library, which holds only what the viewer bought or attended                |
| Support cases                   | The conversations a person opens with the support team                                                                    | Booking requests                                                            |
| Library                         | Only the buyer's or attendee's library                                                                                    | The organization Catalog, whose icon is `LayoutGrid` rather than `Library`  |

In the consultant dashboard, Studio holds what the expert made (Recordings, Session documents and Products), Sell holds the plans the expert prices and schedules, Inbox holds what waits on an answer (Booking requests, Messages and Collaborations), and "My library" is the expert's buyer Library.

## Current navigation trees

Each tree is built by a pure function, so the groups below are what the sidebar renders for a viewer who passes every gate. The breadcrumb labels in each file's `*_PAGE_LABELS` map match the item names.

### Consultant (`buildConsultantNav`)

- Home (path `home`)
- Inbox: Booking requests (badge), Messages (badge), Collaborations (`collaborations`)
- Calendar: Appointments, Availability
- Sell: 1:1 & subscriptions (`sell/sessions`), Group programs (`sell/programs`)
- Studio: Recordings (hosted sessions, `recordings`), Session documents (`documents`), Products (`products`)
- Money: Earnings & payouts, Invite & earn
- Reputation: Reviews
- My library (its own top-level item)
- Settings & help: Help & support, Settings
- Pinned: View public page. Mobile tabs: Home, Requests, Appointments, Messages.

### Consultee (`buildConsulteeNav`)

- Home, Appointments, Messages, Library
- Money: Billing, Invite & earn
- Operations: Help & support, Settings
- Pinned: Find experts. Mobile tabs: Home, Appointments, Library, Messages. Billing opens from the Menu sheet, and the "Needs you" card stays on Home.
- Home and Billing totals are personal, and Home links to each organization the learner belongs to for sponsored sessions. The Personal view lists bookings that no organization hosts; within it, Home's Sessions stat also skips seats an organization rail paid for (WALLET, INVOICE or LICENSE, `lib/payments/org-funded.ts`), such as a seat an organization bought on an independent expert's webinar. "Spent personally" sums this month's settled payments the learner made on a personal rail, whether or not checkout tagged them with an organization. One helper, `appointmentStatusChip` in `lib/appointments/occurrences.ts`, sets the learner's status chip on Home, Appointments and the appointment page: a booked webinar or class reads "Registered", a booked 1:1 (approved or scheduled) reads "Confirmed", and a live webinar or class reads "In progress" from its next session's join window. The Billing page is titled Billing everywhere, including the "Billing › Credits" link on Invite & earn, which no longer repeats the credit history table; its route is still `payments`.

### Organization (`buildOrganizationNav`)

Items appear only when the viewer's role and the organization's capabilities pass the same gates the pages check. The regrouping moved items between groups without changing any gate.

| Group          | Items and their gates                                                                                                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overview       | Every member                                                                                                                                                                                                                                            |
| My work        | My Program (`myProgram.read` and `canSponsor`), Compensation (`myArrangement.read` and `canHost`), Appointments (every member), Booking requests (a consultant profile and `canHost`), Collaborations (`myArrangement.read` and `canHost`, for experts) |
| Messages       | Every member                                                                                                                                                                                                                                            |
| Library        | Every member, one unlabelled item so the group does not restate it                                                                                                                                                                                      |
| People         | Members (`members.directory`)                                                                                                                                                                                                                           |
| Sponsor        | Sponsorship programs (`programs.read`, route `programs`), Contracts (`contracts.read`), Billing (`billing.read`), each also needing `canSponsor`                                                                                                        |
| Host           | Catalog (`catalog.manage`, icon `LayoutGrid`), Collaborations (`catalog.manage`), Payouts (`payouts.read`), each also needing `canHost`                                                                                                                 |
| Insights       | Analytics (`operations.read`), Audit (`audit.read`), Consent (`consent.read`)                                                                                                                                                                           |
| Help & support | Every member; the page is the organization's triage, and each of its tabs carries its own gate                                                                                                                                                          |

My work has five items, one more than the usual limit of about four, because every item in it is gated and most members see two or three of them. A learner on a sponsoring organization sees My Program and Appointments; an expert on a hosting organization sees Compensation, Appointments and Collaborations, plus Booking requests with a consultant profile.

Collaborations (`collaborations`) is one route over `InvitationsPanel` that the server resolves by role. An operator holding `catalog.manage` reads every plan the organization hosts, whoever delivers it, read-only, from the Host group. Any other member who delivers for the organization (`deliversForOrg`) reads their own plans and invitations from My work. Both need `canHost`, and no viewer sees both nav items.

The phone tabs did not change: operators get Overview, Appointments, Members and Billing or Payouts, and members get their own landing page, Appointments and Messages (`organizationMobileTabs`). `__tests__/dashboard/org-nav-gates.test.ts` snapshots the visible item set and phone tabs for every role, capability, suspension and consultant-profile combination (112 in all).

Organization settings is not a rail item. It opens from the avatar menu and from the mobile Menu sheet, which lists the row only for an ACTIVE membership whose role passes `canOpenOrgSettings`. A suspended member sees Overview, Appointments and Library only.

### Workspace (`buildWorkspaceNav`)

- Overview, plus Activity and Spend when the person owns more than one organization
- Operations: Help & support, Workspace settings

## Library

Library means only what the viewer bought, attended or was given access to. One server component, `LibraryPage` in `components/dashboard/library/LibraryPage.tsx`, renders it for every role. Its tabs live in the URL as `?tab=purchases|recordings|documents`, parsed through the `LibraryTabSchema` enum in `lib/dashboard/library-tabs.ts`. An unknown or unavailable tab opens the viewer's first tab. In the organization Library the tab links (`LibraryTabNav`) carry the current `?scope=` from the live URL, because the Mine and Everyone pick rewrites the address bar without a server render. Each tab is a link, so switching tabs is a server navigation and the server reads only the active tab's data:

- Purchases lists `readDigitalProductLibrary()` for the buyer's user id through `DigitalProductLibrary`.
- Session recordings and Session documents seed page 1 of `readRecordingLibrary()` or `readDocumentLibrary()` and hand over to `PersonalLibrary` (learner side) or `OrgLibrary` (organization), which fetch filtered pages on the client.

| Role         | Route                                     | Title      | Tabs                                                                                                                               |
| ------------ | ----------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Learner      | `/dashboard/consultee/<id>/library`       | Library    | Purchases, Session recordings, Session documents                                                                                   |
| Expert       | `/dashboard/consultant/<id>/library`      | My library | Purchases, plus Session recordings and Session documents only when the owner also has a learner profile; one tab hides the tab bar |
| Organization | `/dashboard/organization/<orgId>/library` | Library    | Session documents, Session recordings, each keeping the Mine and Everyone scope (`?scope=`)                                        |

An expert's attended sessions belong to their learner profile, so the expert's recordings and documents tabs read and link to the learner side (`/dashboard/consultee/<learner id>/…`). The organization Library keeps its gates: every member, a suspended one included, reads Mine (`requireOrgAccess` with `allowSuspended`), and Everyone needs an active member with `operations.read` (`libraryScopeFor()`).

The account menu on every surface carries **My library**, which links to `/dashboard/go/library`. `resolveGoHref()` in `lib/dashboard/go.ts` sends a viewer with a learner profile to the learner Library, a viewer with only an expert profile to My library, and anyone else (an organization workspace operator, for example) to `/dashboard`. The go page forwards `?tab=`, so digital product receipts, the product page's "Open library" and "Back to library" links and the purchase email all use `/dashboard/go/library?tab=purchases` (`digitalProductLibraryHref()`); the email makes it absolute. Find matches the learner and expert Library rail items on "purchases", "products", "recordings", "documents", "downloads", "ebooks" and "templates"; the organization Library, which holds only session documents and recordings, answers to "purchases", "recordings", "documents" and "downloads". In a personal tree that already has a Library item, Find skips the account menu's My library row, so a learner sees one Library entry; elsewhere it lists My library under Account. The Sell pages also match "offerings".

## Sell, Studio products and Collaborations

Sell is the two plan pages an expert prices and schedules. Each list page renders through `SellPageShell` (`components/offerings/list/SellPageShell.tsx`): a header with the **+ New** picker, `?tab=` links that navigate, and the active tab's list. The tab enums live in `SELL_TAB_SCHEMAS` (`lib/dashboard/sell-pages.ts`); an unknown or missing `tab` opens the first tab, and no page has more than two tabs.

| Page                | Route                                      | Tabs                         | List                                             |
| ------------------- | ------------------------------------------ | ---------------------------- | ------------------------------------------------ |
| 1:1 & subscriptions | `/dashboard/consultant/<id>/sell/sessions` | Consultations, Subscriptions | `EventManagementDashboard` for one plan kind     |
| Group programs      | `/dashboard/consultant/<id>/sell/programs` | Webinars, Classes            | `EventManagementDashboard` over the planner read |

`SellOfferingsList` passes `EventManagementDashboard` one plan kind. The 1:1 tabs read only their own plan list and skip the planner read; the webinar and class tabs read the planner, which carries the group instances. The search box stays in the URL as `?q=`.

Two pages sit outside Sell and do not use `SellPageShell`:

| Page           | Group  | Route                                       | List                                                                 |
| -------------- | ------ | ------------------------------------------- | -------------------------------------------------------------------- |
| Products       | Studio | `/dashboard/consultant/<id>/products`       | `DigitalProductList`, with one **New digital product** action        |
| Collaborations | Inbox  | `/dashboard/consultant/<id>/collaborations` | `InvitationsPanel`: invitations to co-host and the plans you co-host |

Replay sales are closed, so the dashboards carry no replay listing, tab or "Sell as replay" link. No recording is listed for sale: publishing is closed, and recordings stay with the booking.

The **+ New** picker (`NewOfferingMenu`) offers 1:1 consultation, subscription, webinar, class and digital product. Each opens the existing editor at `offerings/<kind>/new`; editing stays at `offerings/<kind>/<id>/edit`. After a save the editors return to the page that lists that kind (`sellHomeHref()`): the Sell page and tab for a plan, `products` for a digital product. An editor's `offerings` and `<kind>` breadcrumbs open that list too (`sellHomePath()`); for a digital product the first crumb reads Products rather than Sell, so the trail is Products › Digital product › Edit.

## Organization page tabs

No organization page shows more than three tabs. Billing and Payouts render through `TabsWithOverflow` (`components/dashboard/shared/TabsWithOverflow.tsx`), which keeps the active tab in `?tab=` like `UrlTabs`, shows the first three tabs the viewer can see, and lists the rest in a **More** menu beside the tab list. The menu is a Radix dropdown, so it opens with Enter, Space or the arrow keys and closes with Escape. A tab chosen from the menu, or opened by its `?tab=` link, takes the last inline slot and the tab it displaces moves into the menu, so the open panel always has a real, selected tab that labels it, as the WAI-ARIA tabs pattern requires. Each tab keeps its old gate, and a merged tab stacks the old panels, unchanged, one after the other. A stacked section carries an id (`accrued-usage`, `license`, `earnings`, `expert-routing`); when the URL hash names it, `useScrollToHashOnReady()` (`hooks/useScrollToHashOnReady.ts`) scrolls it into view once its panel's data has rendered, once per page load, and jumps instead of animating when the viewer prefers reduced motion.

| Page    | Tab (`?tab=`)                       | What it shows, and when                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Billing | Invoices & usage (`invoices`)       | Invoices, always; then Accrued usage (`#accrued-usage`) when the organization is on INVOICE funding or has accrued postings                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Billing | Wallet & licence (`wallet`)         | The wallet on WALLET funding, or the annual licence (`#license`) on LICENSE funding; hidden on the other rails                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Billing | Purchase orders (`purchase-orders`) | When the organization requires purchase orders and the viewer holds `purchaseOrders.read`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Billing | Payment disputes (`disputes`)       | With `disputes.read`; under More when three tabs are already showing                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Billing | Member spend (`member-spend`)       | On PERSONAL funding with `reimbursements.read`; under More when three tabs are already showing                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Payouts | Runs & earnings (`runs`)            | Payout runs, then Earnings (`#earnings`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Payouts | Payout account (`payout-account`)   | The bank account; only `payouts.account.manage` edits it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Payouts | Rate cards & routing (`rate-cards`) | Rate cards, then Expert routing (`#expert-routing`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Catalog | Webinars, Classes, Materials        | Webinars and Classes list live plans with status chips (All statuses, Published, Drafts) and an Archived chip once something has been withdrawn; `?status=archived` opens on that chip in the first kind with archived plans (Classes when only classes are withdrawn) and, with nothing withdrawn, shows "No archived …" rather than live plans. The Archived chip writes `?status=archived` and the lists read it on every render, so back, forward and links into or out of the archived view always apply. With no experts the lists show "Invite an expert first", and the Archived chip still sits beside it, so withdrawn plans stay reachable |

For example, a WALLET-funded organization that requires purchase orders shows an OWNER Invoices & usage, Wallet & licence and Purchase orders, with Payment disputes under More. An INVOICE-funded organization without purchase orders shows the same OWNER Invoices & usage and Payment disputes, and no More menu.

Each page parses `?tab=` through that page's `z.enum`; a missing or unknown value renders the page on its first visible tab. `invoices`, `wallet`, `purchase-orders`, `disputes`, `member-spend`, `runs`, `payout-account`, `rate-cards`, `webinars`, `classes` and `materials` are the current values. Billing and payout emails and notifications link to the bare `billing` and `payouts` pages, so they open the first tab. The Overview's "Not yet invoiced" figure links to `billing?tab=invoices#accrued-usage`.

## Public pages

The public site follows the same words as the dashboards.

- **Expert profile.** `/explore/experts/<id>` is one scrolling page with a sticky tab bar (`ProfileAnchorTabs`): About, Sessions, Programs, Products and Reviews. Each tab links to a section id (`#about`, `#sessions`, `#programs`, `#products`, `#reviews`). A tab is hidden when its section is empty (no 1:1 or subscription plans, no classes or webinars, no digital products, no reviews), and the bar disappears when only About is left. An `IntersectionObserver` marks the section being read with `aria-current`; the tabs are plain links, so the keyboard and a no-script visit work, and on a narrow screen the bar scrolls sideways. The page's data reads did not change.
- **Products index.** `/explore/products` lists digital products only. The URL carries `q`, `category`, `price`, `sort` and `page`, parsed by `parseProductsQuery()` in `lib/explore/products-query.ts` (a bad or repeated value falls back to its default). `listPublicDigitalProducts()` (`lib/data/digital-products-public.ts`) applies the same `digitalProductDiscoverableWhere()` visibility as the product page, 24 per page, newest first unless sorted by price, cached for 300 seconds under the `digital-products` tag; a free-text `q` search skips the cache. Filtering is a plain GET form and paging is Previous and Next links. `purgeDigitalProductSurfaces()` clears it on publish, edit, archive, moderator takedown and, after commit, on a creator's erasure (which archives their products); `purgeExpertSurfaces()` clears it too, because cards carry the creator's name, so a profile name or avatar change refreshes them. Cards show the amount before GST with a "+ GST" label (`productPriceLabel()`), the same as the expert profile; free products show "Free". The page sits in an `(index)` route group beside `[slug]`, so its `loading.tsx` stays out of the detail pages' ancestors.
- **Breadcrumbs.** Product, replay and the four plan detail pages show Experts › Expert name › Item title through `PublicBreadcrumb` (`components/explore/PublicBreadcrumb.tsx`); a plan with no consultant drops the middle crumb.
- **Account menu.** The signed-in avatar in the public header opens a menu. The first time it opens (the mobile sheet counts as opening it), `useDashboardFacets()` fetches `GET /api/user/dashboard-facets`. The answer stays fresh for 30 seconds, under a query key made of the user id, role, the four profile ids and the active memberships, so any change the session carries (signing in or out, a new profile or membership) refetches at once, and reopening the menu after 30 seconds refetches too. That window also bounds changes the session does not carry, such as a pending or suspended membership. The route runs `resolveDashboardFacets()` with the same inputs as the dashboard ContextSwitcher: the session's profile ids and role, plus every non-deactivated membership (`findSwitcherMemberships()`, shared with `/api/user/org-memberships?all=1`). It answers 401 signed out, `Cache-Control: private, no-store`, and only each facet's kind, key, label and href (`DashboardFacetsResponseSchema`), so the menu lists Expert, Learner (only once a learner profile exists), every organization, All organizations, Admin and Staff exactly as the switcher does. While loading, the menu shows one door per personal profile the session holds plus a skeleton row; if the fetch fails it shows those doors and "All dashboards" (`/dashboard`). My library (`/dashboard/go/library`), Settings (`accountSettingsHref()`) and Sign out are always there, and the mobile sheet lists the same rows. The route is not rate-limited, like `/api/user/org-memberships`, and reads no client IP.

## Routes that did not move

The editors under `offerings/<kind>/…` are live routes. The per-booking pages (`appointments/<id>/documents` and `appointments/<id>/recordings`) did not move, and neither did the expert's hosted Recordings and Session documents pages, which only moved into the Studio group. `/dashboard/go/<facet>/sell/…`, `products`, `collaborations` and `offerings/…` resolve only to the expert side (`EXPERT_ONLY` in `lib/dashboard/go.ts`). A B2C recording-ready or recording-failed notice goes to the host and every attendee with one link, `/dashboard/go/auto/appointments/<id>/recordings` (`appointmentRecordingsHref()` in `lib/novu/resolve-href.ts`); the go page reads the viewer's side of that booking, so the host lands on the booking's hosted recordings and an attendee on their own, never a host on the buyer Library. An org-hosted notice opens the org Library's Session recordings tab, which lists sessions a member attends or delivers. A no-show bell has one learner recipient and links to their Library tab through `personalHref()`, and document notices link each recipient to their own side of the booking's document thread.

## Support wording

The support area is called Support cases wherever the viewer sees it: the first tab of Help & support, the breadcrumb, the case back link and the organization and workspace support page titles. The header Help menu has a personal row that links to the viewer's own cases page. Inside an organization that row reads "My support cases", so it is not mistaken for the organization's triage page behind the sidebar's Help & support; everywhere else it reads "Support cases". Booking "Requests" keeps its name. Find still matches the old words "recordings" and "support requests" through synonyms in `lib/dashboard/nav/find-index.ts`, where each navigation tree can replace a page's shared synonyms with its own (the organization's Sponsorship programs answers to "sponsorship" and "seats", not "webinars" or "classes").

3. A consultant Studio group holding the hosted Recordings, Session documents and Products, the Sell grouping of plans into sessions and group programs, and Collaborations in Inbox (done).
4. The organization regrouping into My work, Sponsor and Host, with Billing and Payouts tabs merged to at most three visible plus a "More" menu (done).
5. Public pages: expert profile anchor tabs, a products index, breadcrumbs and a public header account menu.

## Deprecated & Superseded Approaches

The organization rail used to carry its own "Organization settings" item under Operations, duplicating the avatar menu entry. It was removed, and the mobile Menu sheet no longer skips the settings row when a rail item points at the same page. Do not add the item back.

The support area used to be called "Support requests", with a first tab labelled "Requests". Both are now "Support cases", and "Requests" is reserved for booking requests. The component `SupportRequestView` and the `requestsHref` property keep their old identifiers; only the words the viewer reads changed.

The Catalog item used the `Library` icon, which collided with the learner's Library group. It now uses `LayoutGrid`.

The expert's temporary "My purchases" item (`/dashboard/consultant/<id>/purchases`), the learner's Library group with Session documents, Session recordings and Digital products (`documents`, `recordings` and `products`), and the organization's two Library items (`documents` and `recordings`, with `OrgLibraryPage` rendering each) were replaced by the one Library page per role. The old URLs were deleted, not redirected, and now answer 404; do not link to them or add pages under them.

The public "Recordings Library" at `/explore/recordings` was removed along with the Replays tab of `/explore/products`, which only ever showed an empty state. The index page was deleted and answers 404; `/explore/recordings/<slug>` still serves a replay. Do not link to the old index or add a page back there. The avatar used to be a plain link to Settings with a separate Sign out button; do not restore it.

The consultant's single Offerings item (`offerings`, titled Offerings) held every kind behind a sub-tab bar (`OfferingsTabs`: My offerings, Digital products, Collaborations) and a type pill (All, 1:1, Subscriptions, Webinars, Classes). It was split into the Sell pages, Products and the Collaborations page, and its Business, Library, Grow and Operations groups became Inbox, Calendar, Sell, Studio, Reputation & growth and Settings & help. The Offerings list URLs (`offerings`, `offerings/products`, `offerings/collaborations`) and `planner` were deleted and answer 404; link to `sell/*`, `products` or `collaborations` instead.

Sell briefly held four items: the two plan pages, Products (Digital products and Replays tabs) and Collaborations. Products moved to Studio at `products`, Collaborations to Inbox, and the Replays tab with `ReplaysPanel`, `HostedReplays` and `listHostedReplays()` was deleted. `sell/products` and `?tab=replays` on it answer 404 and are not redirected; link to `products` instead. The expert's home entry used to read "Today" and the booking-style Settings section "Booking requests"; they are Home and Booking mode.

The consultant's Reputation & growth group (Reviews and Invite & earn) and its one-item Money group were regrouped: Invite & earn moved under Money, and the group now called Reputation holds Reviews alone. Do not restore the old group name.

The organization's two collaboration pages, Plan collaborators (`collaborations`) and Collaborators (`collaborators`), merged into one Collaborations route, and its Programs page is titled Sponsorship programs with the `programs` route unchanged. The `collaborators` URL was deleted and answers 404.

The organization rail used to group its items as an unlabelled top group (Overview, My Program, Compensation, Appointments, Messages, Booking requests, Plan collaborators), Library, People, Sponsorship (Programs, Contracts), Hosting (Catalog), Money (Billing, Payouts), Operations (Help & support) and Insights. Those became Overview, My work, Messages, Library, People, Sponsor, Host, Insights and Help & support, with every gate unchanged.

Org Billing used to show up to seven tabs (Invoices, Accrued usage, Wallet, License, Purchase orders, Payment disputes, Member spend), and Payouts showed five (Runs, Earnings, Payout account, Rate cards, Expert routing). They merged into the tabs above. Catalog used to carry Archived and Collaborators tabs; Archived is now a status chip inside the lists, and Collaborators is its own Host item. The retired `?tab=` values (`accrued-usage`, `license`, `earnings`, `expert-routing`, `archived`, `collaborators`) are not aliased: an unknown value opens the default tab. Link to `billing?tab=invoices#accrued-usage`, `billing?tab=wallet#license`, `payouts?tab=runs#earnings`, `payouts?tab=rate-cards#expert-routing`, `catalog?status=archived` or `collaborators` instead.

A missing dashboard URL answers a real 404. Each role root (`consultant/[consultantId]`, `consultee/[consulteeId]`, `organization/[orgId]`, `org-workspace/[orgWorkspaceId]`) checks its id in a server layout, so a missing or not-owned id never reaches a `loading.tsx`, and an unknown segment under `/dashboard` is caught by the back-office `[tree]` layout. Deep detail pages (an appointment, a payment, a support case) still render their skeleton first and can only soft-404.

Redirect stubs were deleted rather than kept, because the product had no external users before launch (see [the decision](../decisions/2026-11-03-dashboard-ia-drop-legacy-redirects.md)). Gone, and answering 404: the consultee `products`, `recordings`, `documents`, `resources`, `help` and `feedback`; the consultant `purchases`, `help`, `feedback` and `settings/security`; the organization `documents`, `recordings`, `purchase-orders`, `reimbursements`, `disputes` and `materials`; and the `/explore/recordings` index. Do not recreate them. The back-office legacy catch-all (`payments`, `refunds`, `payouts`, `disputes`, `approval-payments`, `documents`, `feedbacks`, `data-breaches`), the global `/profile` page, the consultant `/settings/payouts` hop and the org Members `?tab=learners|experts` aliases are gone as well; link to the canonical sections instead. The consultant `settings?tab=` aliases are gone too, but `settings` itself is live and ignores `?tab=`, so an old tab link opens the Settings hub.
