# The offering editor's tabs become tabs, and every full-height dashboard surface shares one height budget

**Date:** 2026-09-13 · **Branch:** `fix/editor-tabs-and-org-messages` · **Follows:** [the dead-over-scroll entry](./engineering-log-2026-09-13-dead-over-scroll.md) · **Scope:** the offering editor and its three pages, the org Messages page, both banner-bearing shells, and the four other viewport-height surfaces.

This entry records seven small things that looked wrong on the deploy preview of #1620 and what each turned out to be. None of them was caused by #1620; every one predates it. Two needed a decision from the product owner, which was taken before the code was written: the editor's section strip becomes a real tab set, and the org Messages page drops its header and goes full-bleed like the personal Messages tabs.

## The offering editor

The page rendered two titles, "New consultation" from the page file's `DashboardHeader` and "New Consultation" from the editor's own sticky band, the second one uppercased by a CSS `capitalize`. The band is the title that survives scrolling and carries the Draft or Published badge, so the page-level header is gone from the consultant create page, the consultant edit page and the org catalog create page, and the band's title is now sentence case.

The strip under that title looked like tabs and was not: it was five jump links over one long form with a scroll-spy highlight. Clicking Extras landed roughly 300 pixels low for three stacked reasons. The trailing sections (Extras, FAQ, the save bar) are shorter than `<main>`, so the scroller runs out of room before Extras can reach the top, and no offset can fix that without adding empty space at the end of the form. The `scroll-mt-36` clearance was about 50 pixels more than the sticky band. And the observer ranked only the entries that changed in the last batch, so "Extras" stayed lit while the tail of Content was what sat under the header. The strip is now a Radix `Tabs` set with one section visible at a time. Every panel is `forceMount`ed and hidden with `data-[state=inactive]:hidden`, so every field stays registered with react-hook-form and values and validation survive a tab switch. When a submit fails validation, `revealFirstError` opens the first tab in manifest order that owns an errored field; slot sections (FAQ, curriculum, roadmap) declare their form field in a new `slotFields` entry so the same lookup covers them. react-hook-form retries its focus-the-first-error step in a `setTimeout` after `onInvalid`, by which time the tab is shown, so focus lands on the field. The `Tabs` root is `display: contents` so the band and the panels stay direct flex children of the form and the save bar's `mt-auto` still pins to the bottom on a short panel.

Two cosmetic items in the same screenshot: Extras was the only section without an icon (it now has `Video`), and the "Record sessions" switch sat on the same line as its label because a switch is `inline-flex` while the select beside it is block-level. The switch now sits in a 36-pixel row under its label, the same height as an input or a select trigger, so the two halves of that row align.

## The org Messages page

The chat panel was sized to `<main>`'s full height, but the org page also rendered a `DashboardHeader` above it, and the shell's `p-6` sits around both. Nothing subtracted those roughly 135 pixels, so the panel overflowed `<main>` and its bottom edge, the composer, was hidden until the user scrolled. The personal Messages tabs use the same formula and get away with it only because they render no header. The panel was also full-bleed under an inset header, and its `-mx-4 sm:-mx-6 lg:-mx-8` margins were copied from the personal shell's responsive padding rather than the org shell's flat `p-6`, so on large screens it poked eight pixels past the content box on each side. The page now mirrors the personal tabs exactly: no header (the breadcrumb already says Messages), `-m-6`, and the shared height budget described next.

The empty-state copy under Conversations read "Book a consultation to start chatting" for an organisation owner. `ChatSidebar` chose its copy by app role alone and ignored the org pin it already resolves. An org-scoped mount now says "Threads appear here once you're part of a session in this organization."

## One height budget for every full-height surface

The dvh calculation the messages tabs, the viewport fill, the chat skeleton and the org page each hand-rolled subtracted the context bar, the mobile tab bar and the maintenance banner, but not the banner a shell can show above `<main>`: the consultant verification banner and the org status banner. A consultant awaiting verification therefore had the same overflow on the personal Messages tab. Both shells now wrap their banner in an element measured by `useCssVarHeight("--dashboard-banner-height")`, a ResizeObserver that mirrors the banner's height into a root CSS variable and resets it to zero when the banner unmounts, the same mechanism `MaintenanceBanner` already uses. A single `.h-dashboard-fill` utility in `app/globals.css` subtracts all four terms, with the mobile tab bar dropped at `md`, and the five call sites use it instead of their own calc. The contract test pins that every one of them does, that the rule names both variables, that the org page renders no header, and that the editor's strip is a mounted-panel tab set with no observer left behind.

The org shell's `<main>` wrapper is now the same `flex min-h-full flex-col` column the personal shell has, which is what the catalog editor's save bar needed for its `mt-auto` to reach the bottom on a short form.

## Verification

`shell-overflow-contract` (19), `offering-manifests`, `editor-adapter-topics`, `sponsor-pricing-hint` and `nav-targets-resolve` pass (78 tests). A cold `tsc --noEmit` is clean. The browser checks on the deploy preview cover the editor's tab switch, the error-to-tab jump on Publish with an empty title, the save bar on a short panel, the org Messages panel's bottom edge, and the personal Messages tab while the verification banner is showing.
