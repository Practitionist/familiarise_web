## Schema Change Summary

| Change Category | New Models | Modified Models | Breaking? |
|---|---|---|---|
| BetterAuth migration | `verification` | `Session`, `Account` (field renames) | No (field mapping) |
| BetterAuth Org plugin | `organization`, `member`, `invitation`, `team`, `teamMember` | `User` (add relation) | No (additive) |
| Enterprise custom | `OrgInvoice`, `OrgSettings`, `RecordingCollection`, `RecordingCollectionItem`, `MemberProgress` | `Recording`, `Payment` (optional fields) | No (additive) |
| Blog/Community (Directus) | None in Prisma | None | No (separate schema) |
| ConvertKit | None | None (existing `Newsletter` model suffices) | No |
| **Total** | **~12 new models** | **~4 modified models** | **No breaking changes** |

All changes are additive. Existing B2C users and data are unaffected. `prisma migrate deploy` will handle all of this cleanly.

## BetterAuth Migration Changes

### Modified Existing Tables (field renames, not table renames)

**Session table:**
- `expires` → `expiresAt`
- `sessionToken` → `token`

**Account table:**
- `providerAccountId` → `accountId`
- `refresh_token` → `refreshToken`
- `access_token` → `accessToken`
- Add `createdAt` and `updatedAt` if missing

### New Tables

**`verification`** — Replaces NextAuth's `VerificationToken`

### Tables to Drop

**`VerificationToken`** — Replaced by BetterAuth's `verification`

## BetterAuth Organization Plugin Tables

These are auto-generated by `npx @better-auth/cli generate` when the Organization plugin is enabled. We extend them with custom fields via BetterAuth's `additionalFields` config.

**`organization`** — Company entity
- Core fields (auto): `id`, `name`, `slug`, `logo`, `metadata`, `createdAt`
- Custom fields (via additionalFields): `plan`, `seatsTotal`, `seatsUsed`, `billingEmail`, `billingCycle`, `industry`, `size`

**`member`** — User membership in org
- Core fields (auto): `id`, `organizationId`, `userId`, `role`, `createdAt`
- Custom fields: `joinedAt`, `department`

**`invitation`** — Pending invitations
- Core fields (auto): `id`, `organizationId`, `email`, `role`, `status`, `expiresAt`, `inviterId`

**`team`** — Teams within organizations
- Core fields (auto): `id`, `name`, `organizationId`, `createdAt`

**`teamMember`** — Team membership
- Core fields (auto): `id`, `teamId`, `userId`, `role`, `createdAt`

**Important**: Because BetterAuth provides these tables, we do NOT create parallel `Organization`/`OrgMember` Prisma models. We extend BetterAuth's models via `additionalFields`. This means the org infrastructure lives in BetterAuth's domain, and our custom enterprise models reference BetterAuth's `organization` and `member` tables.

## Custom Enterprise Models

These are new Prisma models that extend beyond what BetterAuth provides:

### OrgInvoice

```prisma
model OrgInvoice {
  id              String   @id @default(cuid())
  organizationId  String
  invoiceNumber   String   @unique  // ORG-INV-YYYYMM-XXXXX
  amount          Int               // smallest currency unit
  currency        String   @default("INR")
  status          String   @default("PENDING")
  items           Json              // line items
  pdfUrl          String?
  dueDate         DateTime?
  paidAt          DateTime?
  taxAmount       Int?
  taxRate         Float?
  hsnCode         String?  @default("999293")

  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
}
```

### OrgSettings

```prisma
model OrgSettings {
  id              String   @id @default(cuid())
  organizationId  String   @unique
  customBranding  Json?    // logo, colors, domain
  ssoConfig       Json?    // SAML/OIDC provider config
  allowedDomains  String[] // email domains for auto-join
  defaultRole     String   @default("MEMBER")

  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
}
```

### RecordingCollection

```prisma
model RecordingCollection {
  id              String   @id @default(cuid())
  organizationId  String
  name            String
  description     String?
  isPublic        Boolean  @default(false)

  recordings      RecordingCollectionItem[]

  createdAt       DateTime @default(now())
}
```

### RecordingCollectionItem

```prisma
model RecordingCollectionItem {
  id              String   @id @default(cuid())
  collectionId    String
  recordingId     String
  order           Int      @default(0)

  collection      RecordingCollection @relation(fields: [collectionId], references: [id], onDelete: Cascade)
  recording       Recording           @relation(fields: [recordingId], references: [id])
}
```

### MemberProgress

```prisma
model MemberProgress {
  id              String   @id @default(cuid())
  memberId        String   // BetterAuth member ID
  recordingId     String
  watchedDuration Int      @default(0)  // seconds
  completedAt     DateTime?
  lastWatchedAt   DateTime?

  recording       Recording @relation(fields: [recordingId], references: [id])

  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt

  @@unique([memberId, recordingId])
}
```

## Migration Risk Assessment

This is an **additive change** — all new models and optional relations. This means:

- **No breaking changes** to existing tables
- `prisma migrate deploy` should work cleanly
- No need to "format the database" for existing customers
- Existing B2C users are unaffected since all org relations are optional

The riskier scenario would be if you later need to retrofit existing B2C data into organizations (e.g., a consultee's company wants to claim their account), but that's a data migration, not a schema migration.

## Implementation Order

1. **BetterAuth migration** — field renames on Session/Account, add verification table, drop VerificationToken
2. **Enable Organization plugin** — auto-generates organization, member, invitation, team, teamMember tables with custom fields
3. **Add custom enterprise models** — OrgInvoice, OrgSettings, RecordingCollection, RecordingCollectionItem, MemberProgress
4. **Modify existing models** — add optional organizationId to Payment, add relations to Recording
5. **Enable SSO plugin** — configuration-level change, no schema changes
6. **Enable API Key plugin** — adds apikey table automatically
