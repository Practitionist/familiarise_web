# Notification journey audit

Tracking: [issue 2589](https://github.com/Practitionist/familiarise_web/issues/2589). [Architecture, state and sequence diagrams](https://github.com/Practitionist/familiarise_web/issues/2589#issuecomment-6654354395). Baseline `500308fed`, inspected 2026-11-05. Worktree `fw-notification-mega`, branch `fix/notification-mega-audit`.

This is a code and read-only integration audit. “Inspected” means the named producer, shared delivery path and available tests were reviewed; it does not mean every branch was executed, a live email arrived, or every vendor configuration was accessible. No real sends, broadcasts, provider changes, DB mutations or deploys were performed.

## Current delivery contract

A journey comprises a committed business change, authorized recipients, policy, durable staging, provider attempt, retry, delivery evidence, destination and operator recovery. Template existence alone does not establish coverage.

Email uses `FailedEmail`; newsletters use `FailedEmailBatch`; bells use `NotificationOutbox`. Transactional producers must use the same `tx` for recipient reads and row writes. Rendering belongs outside long transactions where possible. Post-commit network attempts and cron relays share event identity. Email provider acceptance is separate from callback delivery state. Novu workflow families are in-app only.

Optional email obeys master/channel/category/workspace routing. Required email bypasses optional settings. Bell settings remain independently enforced. Suppression and pre-launch guards apply at the wire boundary. Single-use credential bodies are redacted and never replayed.

## Verification and resumption

Targeted regression coverage includes workspace routing/required email, suppression after staging, revoked newsletter recipients, malformed batches, quiet-hours activation, urgent workflows, unknown users, transaction-client isolation, duplicate staged results, distinct payouts, and announcement activation/atomic staging failure.

Validation on the final code: the focused notification selection passed 35 suites / 258 tests. The related-test selection ran 536 suites / 5,177 tests: 531 suites passed initially; five older fixtures omitted the newly mandatory preference reads. After correcting those fixtures, all five passed independently (34 tests). Together these results cover all 5,177 related tests on the final implementation; this is not a claim of one entirely green monolithic invocation.

Typecheck passed with an 8 GB Node heap after the default heap exhausted memory. Full lint passed with zero errors and 218 advisory warnings; changed and new TypeScript files also lint cleanly. Repository-wide formatting reports 216 existing files; none is modified by this PR. Changed/new files pass formatting checks.

CodeRabbit local review was attempted with the repository rules and untracked files included. Its service rejected the CLI session/Git provider authentication despite auth status reporting the expected organization. No findings were stored; automated review remains incomplete. Manual diff inspection and test evidence do not substitute for a completed external review. The SQL backlog change is typechecked and reviewed statically; the shared DB was not queried to execute it. Mocked tests do not certify provider configuration.

The follow-up adds `FailedEmail.deliveryPolicy` and makes recipient category explicit in the typed preparation path. The focused email/notification suite passes 28 suites / 216 tests, including current preferences, routing, required-mail overrides, malformed metadata, changed/erased accounts, and fail-closed read errors. This is an additive schema change: Prisma generation/validation are local, while shared-database rollout remains a human action. The metadata is excluded from provider payloads. The read-only live schema gate confirms exactly one missing required object, `FailedEmail.deliveryPolicy`; deployment and shared-database previews must wait for the canonical human-run rollout. Related-test selection passed 534 suites / 5,194 tests in one run. Typecheck and full lint passed (zero errors, 218 advisory warnings); Prisma validation/generation passed. CodeRabbit again rejected CLI/Git provider authentication, so external review remains incomplete. Changed/new files pass formatting.

Remaining work should resume from the open findings above in P1 → P2 → P3 order. External actions need configuration review and live verification separately. Keep the tracking issue open until those findings have explicit resolution evidence.

## Deprecated & Superseded Approaches

Historical diagrams described future email/push channels and Sentry as the universal telemetry sink. Current Novu families are in-app only; Better Stack owns operational alerts. A template-parity assertion does not replace producer, transaction, recovery, consent or vendor evidence. Preserve this distinction when closing old notification issues.
