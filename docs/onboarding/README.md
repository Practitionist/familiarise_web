# Onboarding

This directory documents how a signed-up user becomes a consultant, a learner or an organisation operator, and everything that follows from that choice until the account is production-ready. Read the documents in order the first time; each later one assumes the vocabulary of the earlier ones.

| Document                                                                   | What it covers                                                                                                                                                                                  |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [01-system-reference.md](01-system-reference.md)                           | The wizard, the invitee/SSO gate and org-owner completion, the validation layers, the draft row (version CAS), the claim-first transaction, the interim funnel query.                           |
| [02-identity-and-org-permutations.md](02-identity-and-org-permutations.md) | The identity matrix: `User.role` × org capability × `MemberRole`, which combinations are legal, which are refused with a code, and how an onboarded learner or operator adds an expert profile. |
| [03-availability-contract.md](03-availability-contract.md)                 | The one rule set every availability write shares, the schedule-type switch guard, the shrink notice, and the profile-completion score.                                                          |
| [04-verification-lifecycle.md](04-verification-lifecycle.md)               | Documents from upload to decision: ownership and quotas, the one submission writer, the one review writer, the bounded NEEDS_INFO loop, and the daily sweep.                                    |
| [05-schema-reference.md](05-schema-reference.md)                           | Why each onboarding and verification column exists, and how the schema change is applied.                                                                                                       |
| [dynamic-tags-strategy.md](dynamic-tags-strategy.md)                       | How skills ("tags" in the model) are proposed and curated.                                                                                                                                      |
