# Job-runtime experiments, 2026-10-31

This folder is the index to the raw reports from the throwaway experiments that tested how background jobs behave on different runtimes. The reading guide and the comparison matrix are in [Background-job runtime options](../../14-background-job-runtime-options.md). The decision context and the open questions are in [Job-runtime experiments (evidence record)](../../../decisions/2026-10-31-job-runtime-experiments.md). Agents read the short versions in `.claude/skills/jobs/references/job-runtime-options.md` and `.claude/skills/deployment/netlify/job-runtime-options.md`.

## 1. Method

The method was the same for every experiment.

- Each experiment ran in its own scratch directory outside the repository, with credentials supplied through environment variables only.
- Every probe measured the same things where it could: connect time, 50 sequential `SELECT 1` round trips (median and p95), a 20-query read mix, and a ten-round-trip row-lock hold (`SELECT … FOR UPDATE`, eight statements, `COMMIT`) on a scratch table. The lock-hold shape is the same everywhere so that the runtimes are comparable.
- Database work used schemas named `lab_*` on the shared Supabase project (Mumbai, `ap-south-1`), dropped at the end of each run. The shared project holds mock data only, and these runs were owner-authorised. Each report ends with a cleanup proof. A rerun defaults to a local or separate disposable database (see the rerun steps in `.claude/skills/jobs/references/job-runtime-options.md`).
- The Netlify and Vercel probes pinned the function region (`ap-southeast-1` and `bom1`) and confirmed it at runtime from inside the function.
- Library and CLI versions are recorded in every report, because the queue libraries and the Inngest SDK change defaults between releases.
- Raw `pg` was used for latency probes, so the numbers exclude Prisma.
- Several probes turned off TLS certificate verification (`rejectUnauthorized: false`) against the mock database. That is a lab-only shortcut and never production guidance; the certificate-verified Cloudflare path is the Hyperdrive one.

## 2. Honesty labels

- **MEASURED** means a run between 2026-10-31 and 2026-11-01 produced the number, and the report holds the log.
- **DOCS** means an official vendor page says so. The pages and quotes are in section 10 of the explanation page.
- **UNVERIFIED** means no primary source was read, or the vendor page contradicts itself.
- **Laptop numbers are best-case.** The laptop is about 40 ms from Mumbai. It is not a prediction for any production host.
- **The Netlify Singapore round trip is now measured.** Raw `pg` measured 62–64 ms per statement. The older figure of about 95 ms was measured through the app and is quoted from the ticker decision record. A bare Prisma client running raw queries measured below noise in `bom1` (0.1 ms or less per statement). That probe did not exercise the app's extended client, model operations or the Netlify cold path, so the gap between 95 ms and 62–64 ms is unexplained.
- **Local dev servers say nothing about the cloud service.** The Inngest runs and the first Upstash Workflow runs used local dev servers. The real QStash EU run is in its own report.
- **Dollar figures are from vendor pages read on 2026-10-31** and may have changed.
- **Redactions.** Tokens, connection strings, project identifiers and the laptop address were removed. Keep it that way when appending.
- **Async Workloads needed a linked repository.** The first attempt was blocked because a CLI deploy lacks the extension's functions. A second attempt linked a throwaway private repository through a deploy key and measured everything. A PR Deploy Preview was also not tested for Background Functions.
