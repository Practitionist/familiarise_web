# Restate Cloud as a durable-execution engine for jobs on Supabase Mumbai

Date 2026-10-31. Laptop in India. Restate Cloud Free, EU environment `<environment-id>.env.eu.restate.cloud` (ingress :8080, admin :9070).
Service on Vercel Hobby, functions pinned to `bom1` (MEASURED: x-vercel-id `bom1`), maxDuration 300, Node 26 local / Vercel Node, `@restatedev/restate-sdk` 1.18.0 (fetch handler), pg 8.23.1, Restate CLI 1.8.1. DB: Supabase pooler ap-south-1 port 6543, schema `lab_rst`.
Code (this folder): `api/restate.ts` (service "Lab": ping, steps, flaky, sleeper, slow, idem, dual, delayed, cron), `vercel.json` (rewrite /api/restate/:path* -> /api/restate), `lib.mjs`, `setup.mjs`, `m1.mjs`, `m2.mjs`, `m5.mjs`, `m8.mjs`, `m9.mjs`, `hop.mjs`.

**Request identity verification was DISABLED.** No admin endpoint exposes the environment's public key (MEASURED: not in admin OpenAPI), so the endpoint was public. Not production-safe. DOCS: https://docs.restate.dev/services/deploy/vercel.md step 2 requires it for public Vercel endpoints. Mock data only; the Vercel project was deleted at the end.

Setup lessons (MEASURED): (a) an Admin-role API key gets 403 on the ingress; ingress calls need a Full-role key (DOCS: https://docs.restate.dev/llms-full.txt). (b) Vercel plain-function `[...path].ts` did not match `/invoke/Lab/ping` (404, Restate retried 8x with backoff); fix was a rewrite to a single `api/restate.ts`. (c) Per-deployment Vercel URLs sit behind Vercel SSO (Restate discovery got 302); the production alias was used. Register with `--use-http1.1` (DOCS vercel.md).
